# draw.io 連携

draw.io 連携の現況と、なぜその形になっているかは spec にまとまっている。ここには根拠を書かない（二重管理になり、必ず古くなる方が残る）。

- spec: [`.kiro/specs/drawio/`](../../../../../.kiro/specs/drawio/)
- 本体: [`design.md`](../../../../../.kiro/specs/drawio/design.md)

## 変更する前に読む節

`design.md` の次の 2 節は、**実測で否定された形と、その結果採った形**を記録している。読まずに直すと否定された形に戻る。

- `なぜ後から直せないのか` — 一度実装してから実測で否定した 2 つの形
- `2 つの入口` — 実測で分かった制約から、入口を 2 つに分けざるを得ない理由

## draw.io のコードはこのディレクトリに閉じていない

エディタの起動、ビューアの描画、保存形式、挿入操作、設定は `features/drawio/` の外にある。どの関心がどのファイルにあるかの一覧は `design.md` の `関心マップ` にある。ここだけを見て変更の影響範囲を決めない。

## 単体テストだけでは足りない

実際に描画されるか、外部への要求が出ないか、ページ送りが保たれるかは自動テストで捕まらない。

- 担保が無いものの一覧: `design.md` の `自動テストで担保していないこと（要件 10.1）`
- 確かめ方: `design.md` の `手動確認の手順（要件 10.2〜10.5）`
