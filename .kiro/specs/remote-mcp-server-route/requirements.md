# Requirements Document

## Project Description (Input)

umbrella `remote-mcp-server` の sub-spec。背景・範囲・制約の詳細は [brief.md](./brief.md)、調査で確かめた事実は [research.md](../remote-mcp-server/research.md) にある。

**誰が困っているか**: GROWI の利用者と、その利用者に AI 連携を提供したい管理者。利用者は、claude.ai などの MCP クライアントから、自分の閲覧権限の範囲で wiki を検索・閲覧したい。

**現状**: GROWI 本体には MCP クライアントが接続できる入口が無い。AI チャット用の全文検索ツールとページ本文取得ツールはあるが、GROWI の中のエージェントからしか呼べない。全文検索ツールは `searchService` を requestContext から読むので、MCP サーバー経由ではそのまま動かない。`accessTokenParser` はクエリとボディの `access_token` も受け付ける。

**何を変えるか**: `@mastra/mcp` の `MCPServer` を、既存の Express に `POST /_api/v3/mcp` としてマウントする。

- 管理者が MCP 連携を有効にしたときだけ応答する（既定は無効。LLM の設定は要らない）。
- アクセストークンは `Authorization: Bearer` ヘッダーでだけ受け付け、既存の `accessTokenParser` で検証する。この認証は暫定で、リリース時には `remote-mcp-server-oauth` が「認可サーバーが発行したトークンだけを受け付ける」認証に差し替える。
- 全文検索とページ本文取得の 2 ツールを、トークンの持ち主の閲覧権限の範囲で公開する。全文検索ツールは `searchService` を外から注入できる形に作り直す。
- セッションを持たず、複数インスタンス構成でどのインスタンスが受けても同じ結果を返す。
- `@mastra/mcp` は起動時に読み込まず、有効なときの最初のリクエストで読み込む。
- `/_api/v3/mcp` に利用者単位の回数制限をかけ、Activity を記録する。
- `/.well-known/*` と 401 の `WWW-Authenticate` チャレンジは出さない。後続の `remote-mcp-server-oauth` が、この spec のツールと、認証より後ろの処理を変更せずに足せるようにする。

この spec だけではリリースしない。`remote-mcp-server-oauth` と合わせてリリースする。

### 確定済みの要件判断（ユーザー確認済み、2026-11-24）

1. **リリース時の MCP エンドポイントは、認可サーバーが発行したトークンだけを受け付ける。** 利用者が個人設定で手動発行したアクセストークンは、リリース時には受け付けない。discovery の時点の「手動発行のトークンでも使えるままにする」は取り消す。
2. **この spec の間は、暫定としてアクセストークンで認証する。** 認可サーバーがまだ無いためである。旧形式の API トークンではなくアクセストークンを使うのは、スコープ・有効期限・ハッシュでの保存を持ち、認可サーバーが発行するトークンと同じ形をしているからである。スコープ不足や期限切れの応答まで、この spec の検証で確かめられる。
3. **トークンは `Authorization: Bearer` ヘッダーでだけ受け付ける。** `X-GROWI-ACCESS-TOKEN` ヘッダーは受け付けない。OAuth のクライアントは `Authorization: Bearer` しか送らないためである。
4. **Basic 認証つきの環境は、リバースプロキシの除外設定を必須とする。** `Authorization` ヘッダーを Basic 認証と取り合うので、代替手段は用意しない。
5. **MCP エンドポイントのパスは `/_api/v3/mcp` にする（2026-11-25 確認）。** 既存の API と同じ場所に置く。`/_api` 配下はページを作れないパスなので、wiki のページと衝突しない。discovery の時点の `/mcp` は取り消す。
6. **MCP の Activity のアクションは、監査ログのどのグループにも入れない（2026-11-25 確認）。** 対応アクションとして定義するだけにする。既存の「ページの閲覧」と同じ扱いで、監査ログが有効で、管理者が追加の設定でそのアクションを記録対象にしたときだけ残る。既定では記録されない。グループへの追加は、必要になってから決める。
7. **複数の呼び出しを 1 つにまとめたリクエスト（バッチ）は受け付けない（2026-11-25 確認）。** 2025 年の各版は、1 回のリクエストに複数の呼び出しを配列でまとめられる。受け付けると、1 回分の回数で多数のツール呼び出しができ、回数制限が効かなくなる。2026-07-28 版はバッチを廃止している。

### 要件判断（推奨案のまま設計に進んだ、2026-11-25）

brief の未決の論点と、起草中に出てきた論点について、次の案を採って要件を書いた。利用者に 8 点を提示したうえで、個別の異論が無いまま `/kiro-spec-design` が実行されたので、承認されたものとして扱う。

1. **要求するスコープは、既存の「ページの閲覧」（`read:features:page`）にする。** ページ取得と全文検索の API がすでに要求しているスコープで、公開する 2 ツールの内容と一致する。リリース後も、認可サーバーが発行するトークンに同じスコープを要求する。
2. **Activity はツール呼び出しの単位で記録する。** 接続確認とツール一覧の取得は記録しない。`/_api/v3/mcp` は 1 つの入口ですべての種類のリクエストを受けるので、リクエスト単位で記録すると、利用者が何もしていない記録で監査ログが埋まる。
3. **有効化のフラグは「MCP 連携全体」で 1 つにする。** `remote-mcp-server-oauth` が足す認可サーバーも、同じフラグで一緒に切り替わる前提にする。管理者が切り替えるものを 1 つに保つためである。
4. **単独でリリースしないことは、ブランチの運用で守る。** この spec の実装は統合ブランチ `feat/remote-mcp-server` へ入り、`remote-mcp-server-oauth` が揃うまで master へ入らない。そのため、管理画面の項目を隠すなどの仕組みは作らない。
5. **メンテナンスモード中は `/_api/v3/mcp` を止める。** 既存の API と同じ扱いにする。
6. **MCP 連携が無効のとき、`/_api/v3/mcp` は存在しないパスと同じ応答を返す。** 無効な GROWI が、MCP の入口を持つことを外へ知らせないためである。
7. **ゲストの閲覧を許している wiki でも、トークンなしでは使えない。** 回数制限と Activity の記録が、利用者を特定できることを前提にしているためである。
8. **全文検索が使えない GROWI でも、全文検索ツールは一覧に出す。** 呼び出されたら、検索が使えないことを結果として返す。ツールの一覧が GROWI の設定によって変わらないようにするためである。

## Introduction

本機能は、GROWI 本体に MCP（Model Context Protocol）の入口 `/_api/v3/mcp` を追加する。管理者が MCP 連携を有効にすると、アクセストークンを持つ利用者は、MCP クライアント（claude.ai、Claude Code など）から、自分の閲覧権限の範囲で wiki を全文検索し、ページの本文を読める。

本機能は単独ではリリースしない。本機能の段階では、利用者が個人設定で発行したアクセストークンで認証する。これは開発と検証のための暫定の認証である。後続の `remote-mcp-server-oauth` が、MCP クライアントの画面でサインインして接続する方式を追加し、MCP エンドポイントの認証を「認可サーバーが発行したトークンだけを受け付ける」ものに差し替える。リリースされるのは差し替えたあとの姿である。

本書で使う用語は次のとおり。

- **MCP 連携**: 管理者が切り替える設定。有効のときだけ MCP エンドポイントが応答する。
- **MCP エンドポイント**: GROWI の `/_api/v3/mcp`。MCP クライアントが接続する入口。
- **MCP クライアント**: MCP エンドポイントに接続するアプリ。
- **アクセストークン**: 有効期限とスコープを持つ GROWI のトークン。
- **ツール**: MCP クライアントが呼び出せる機能。本機能は全文検索とページ本文取得の 2 つを公開する。
- **ツール呼び出し**: MCP クライアントが、ツールの実行を求めるリクエスト。
- **接続確認**: MCP クライアントが、接続の開始時やサーバーの情報を得るために送るリクエスト。ツールの実行を伴わない。

## Boundary Context

- **In scope**:
  - MCP エンドポイントの応答と、MCP 連携の有効・無効の切り替え
  - リクエストヘッダーのアクセストークンによる利用者の特定
  - 全文検索ツールとページ本文取得ツールの公開
  - MCP エンドポイントの回数制限
  - ツール呼び出しと設定変更の Activity 記録
  - 管理画面での切り替えと、MCP エンドポイントの URL の表示
- **Out of scope**:
  - MCP クライアントの画面でサインインして接続する方式。認可サーバーの案内（`/.well-known/*` と、401 応答に付ける認可サーバーの案内）を含む（`remote-mcp-server-oauth`）
  - アクセストークンの発行・失効・一覧
  - ページの作成・更新・削除など、書き込みを伴うツール
  - GROWI の AI エージェントを MCP のツールとして公開すること
  - Basic 認証つきの環境向けの、リバースプロキシの設定手順の文書
- **Adjacent expectations**:
  - **認可サーバーの案内を出さない**: 本機能は、認可サーバーの案内を一切出さない。claude.ai は、認可サーバーの案内を見つけたのにクライアントの登録方法が無いと、接続を拒否する。案内は、`remote-mcp-server-oauth` が認可サーバーを揃えたときに初めて出す。
  - **`remote-mcp-server-oauth` への期待**: 同 spec は、Requirement 2 の暫定の認証を、認可サーバーが発行したトークンだけを受け付ける認証に差し替え、未認証時の応答へ認可サーバーの案内を足す。本機能のツールと、利用者を特定したあとの処理（Requirement 3〜8）は変えない。要求するスコープと MCP 連携の設定は、本機能が決めたものを使う。
  - **Basic 認証つきの環境**: リバースプロキシで Basic 認証をかけた GROWI では、プロキシが MCP エンドポイントを Basic 認証の対象から外さない限り、リクエストが GROWI に届かない。本機能は、この環境向けの代替の認証手段を持たない。
  - **アクセストークンの検証**: トークンの有効期限・スコープの判定・閲覧専用の利用者の扱いは、既存のアクセストークンの検証に従う。本機能はこれを緩めない。既存の検証は、閲覧専用の利用者のアクセストークンを受け付けない。そのため、閲覧専用の利用者は MCP エンドポイントを使えない。
  - **閲覧権限の判定**: ページを見られるかどうかの判定は、既存のページ閲覧と全文検索の判定に従う。
  - **AI 機能の設定**: 本機能は LLM を呼ばない。GROWI AI の有効・無効や LLM の設定に左右されない。
  - **既存の AI 機能**: AI チャットと suggest-path が使う全文検索ツールとページ本文取得ツールの結果は、本機能の追加の前後で変わらない。

## Requirements

### Requirement 1: 管理者による MCP 連携の切り替え

**Objective:** As a 管理者, I want MCP 連携を自分の判断で有効・無効にしたい, so that 外部の AI クライアントに wiki を公開するかどうかを管理できる

#### Acceptance Criteria

1. The GROWI shall MCP 連携を既定で無効にする。
2. When 管理者が管理画面で MCP 連携を有効にしたとき, the GROWI shall 再起動なしで MCP エンドポイントの応答を始める。
3. When 管理者が管理画面で MCP 連携を無効にしたとき, the GROWI shall 再起動なしで MCP エンドポイントの応答を止める。
4. While MCP 連携が無効のあいだ, the MCP エンドポイント shall アクセストークンの有無にかかわらず、存在しないパスと同じ応答を返す。
5. While MCP 連携が有効のあいだ, the 管理画面 shall 利用者に案内する MCP エンドポイントの URL を表示する。
6. If GROWI のサイト URL が設定されていないとき, the 管理画面 shall MCP エンドポイントの URL の代わりに、サイト URL の設定が必要であることを表示する。
7. If 管理者でない利用者が MCP 連携の設定を読もうとした、または変えようとしたとき, the GROWI shall その操作を拒否する。
8. The GROWI shall GROWI AI が無効、または LLM が未設定の状態でも、MCP 連携の有効化を受け付ける。
9. While GROWI AI が無効、または LLM が未設定のあいだ, the 管理画面 shall MCP 連携の設定を、操作できる状態で表示する。

### Requirement 2: アクセストークンによる認証（暫定）

**Objective:** As a 開発者・検証者, I want アクセストークンで MCP エンドポイントに接続したい, so that 認可サーバーが揃う前に、MCP エンドポイントとツールの動作を実際の MCP クライアントで確かめられる

本 Requirement は、`remote-mcp-server-oauth` が認証を差し替えるまでの暫定である。差し替えたあとも、基準 4・7・8・9・10・11（未認証時の振る舞い）は保たれることを期待する。

#### Acceptance Criteria

1. When 「ページの閲覧」のスコープを持つ有効なアクセストークンが `Authorization: Bearer` ヘッダーで送られたとき, the MCP エンドポイント shall そのトークンの持ち主としてリクエストを処理する。
2. If アクセストークンが `X-GROWI-ACCESS-TOKEN` ヘッダーだけで送られたとき, the MCP エンドポイント shall そのトークンを認証に使わず、認証が必要であることを示すエラー（401）を返す。
3. If アクセストークンが URL のクエリ、またはリクエストの本文だけで送られたとき, the MCP エンドポイント shall そのトークンを認証に使わず、401 を返す。
4. If `Authorization: Bearer` ヘッダーが無いとき, the MCP エンドポイント shall 401 を返す。
5. If 送られたアクセストークンが、存在しない・期限切れ・「ページの閲覧」のスコープを持たない、のどれかに当たるとき, the MCP エンドポイント shall 401 を返す。
6. If 旧形式の API トークンが送られたとき, the MCP エンドポイント shall そのトークンを認証に使わず、401 を返す。
7. If ブラウザのログインセッションだけを持ち、有効なトークンを持たないリクエストが届いたとき, the MCP エンドポイント shall 401 を返す。
8. While wiki がゲストの閲覧を許しているあいだ, the MCP エンドポイント shall 有効なトークンの無いリクエストに 401 を返す。
9. The MCP エンドポイント shall 401 の応答で、ログイン画面へのリダイレクトを行わない。
10. The MCP エンドポイント shall 401 の応答の本文で、トークンが拒否された理由（存在しない・期限切れ・スコープ不足）を区別して伝えない。
11. The MCP エンドポイント shall 利用者を特定する方法が差し替わっても、ツールの結果・回数制限・Activity の記録が同じ利用者を基準に動くようにする。

### Requirement 3: MCP クライアントとの接続

**Objective:** As a 利用者, I want 手元の MCP クライアントをそのまま接続したい, so that クライアントの種類や GROWI の構成を気にせずに使える

#### Acceptance Criteria

1. When 認証済みの MCP クライアントが接続確認を送ったとき, the MCP エンドポイント shall MCP サーバーとしての情報を返す。
2. When 認証済みの MCP クライアントがツールの一覧を求めたとき, the MCP エンドポイント shall 全文検索ツールとページ本文取得ツールの 2 つを返す。
3. The MCP エンドポイント shall MCP 仕様の 2026-07-28 版のクライアントと、2025 年の各版（2025-03-26、2025-06-18、2025-11-25）のクライアントの両方からの接続を受け付ける。
4. The MCP エンドポイント shall 各リクエストを、それ以前のリクエストの状態に頼らずに処理する。
5. While GROWI が複数のインスタンスで動いているあいだ, the MCP エンドポイント shall どのインスタンスがリクエストを受けても同じ結果を返す。
6. If MCP クライアントが、リクエストの送信以外の操作（サーバーからの通知を待つ接続、セッションの終了）を求めたとき, the MCP エンドポイント shall その操作に対応していないことを示すエラーを返す。
7. The MCP エンドポイント shall ツールの一覧で、各ツールが読み取り専用であることを MCP クライアントに伝える。
8. The MCP エンドポイント shall ツールの一覧で、各ツールの用途と入力の意味を、MCP クライアントの AI が使い分けられる説明として返す。
9. The MCP エンドポイント shall ツールの一覧を、GROWI の全文検索の設定にかかわらず同じ内容で返す。
10. While GROWI がメンテナンスモードのあいだ, the MCP エンドポイント shall メンテナンス中であることを示すエラー（503）を返す。
11. If MCP クライアントが、複数の呼び出しを 1 つにまとめたリクエストを送ったとき, the MCP エンドポイント shall そのリクエストに含まれる呼び出しを 1 つも実行せずに、リクエストが不正であることを示すエラーを返す。

### Requirement 4: 全文検索ツール

**Objective:** As a 利用者, I want MCP クライアントから wiki を全文検索したい, so that 必要なページを Claude に探させられる

#### Acceptance Criteria

1. When 認証済みの MCP クライアントがキーワードを指定して全文検索ツールを呼び出したとき, the 全文検索ツール shall トークンの持ち主が閲覧できるページだけを検索結果として返す。
2. The 全文検索ツール shall 検索結果の各ページについて、ページの ID・パス・一致箇所の抜粋を返す。
3. The 全文検索ツール shall 一致した総件数を返す。
4. Where 件数の上限が指定されたとき, the 全文検索ツール shall 指定された件数まで（最大 20 件）の結果を返す。
5. Where 並び順が指定されたとき, the 全文検索ツール shall 関連度・作成日時・更新日時のうち指定された基準で結果を並べる。
6. When 検索に一致するページが無いとき, the 全文検索ツール shall 0 件の結果を、エラーではなく正常な結果として返す。
7. If GROWI の全文検索が使えない状態のとき, the 全文検索ツール shall 全文検索が使えないことを結果として返す。
8. If 検索の実行中にエラーが起きたとき, the 全文検索ツール shall 検索に失敗したことだけを結果として返し、内部のエラーの詳細を含めない。
9. The 全文検索ツール shall 同じ利用者・同じ検索条件について、GROWI の画面での全文検索と同じ範囲のページを対象にする。

### Requirement 5: ページ本文取得ツール

**Objective:** As a 利用者, I want MCP クライアントからページの本文を読みたい, so that 検索で見つけたページの内容を Claude に参照させられる

#### Acceptance Criteria

1. When 認証済みの MCP クライアントがページの ID を指定してページ本文取得ツールを呼び出したとき, the ページ本文取得ツール shall トークンの持ち主が閲覧できる場合に、そのページの内容を返す。
2. When 認証済みの MCP クライアントがページのパスを指定してページ本文取得ツールを呼び出したとき, the ページ本文取得ツール shall トークンの持ち主が閲覧できる場合に、そのページの内容を返す。
3. The ページ本文取得ツール shall 返す内容に、ページの ID・パス・総行数を含める。
4. When 行の範囲を指定せずに長いページが求められたとき, the ページ本文取得ツール shall 本文の代わりに見出しの一覧を返す。
5. When 行の範囲が指定されたとき, the ページ本文取得ツール shall その範囲の本文（1 回につき最大 500 行）と、続きがあるかどうかを返す。
6. If 指定されたページが存在しない、またはトークンの持ち主に閲覧権限が無いとき, the ページ本文取得ツール shall どちらの場合も同じ内容の結果を返す。
7. If ページの ID もパスも指定されていないとき, the ページ本文取得ツール shall 入力が足りないことを結果として返す。
8. If ページの取得中にエラーが起きたとき, the ページ本文取得ツール shall 内部のエラーの詳細を結果に含めない。
9. The ページ本文取得ツール shall エラーの結果によって、ページが存在するかどうかを推測できないようにする。

### Requirement 6: 回数制限

**Objective:** As a 管理者, I want MCP エンドポイントへのリクエスト数を制限したい, so that 1 人の利用者や 1 つのクライアントの大量のリクエストで wiki 全体が重くならない

#### Acceptance Criteria

1. The MCP エンドポイント shall 認証済みのリクエストの回数を、利用者ごとに数える。
2. If 1 人の利用者のリクエストが一定時間あたりの上限を超えたとき, the MCP エンドポイント shall その利用者のリクエストを、回数の超過を示すエラー（429）で拒否する。
3. While ある利用者が上限を超えているあいだ, the MCP エンドポイント shall 同じ送信元アドレスから届く、他の利用者のリクエストを処理し続ける。
4. If 認証されていないリクエストが、1 つの送信元アドレスから一定時間あたりの上限を超えて届いたとき, the MCP エンドポイント shall その送信元のリクエストを 429 で拒否する。
5. The GROWI shall 運用者が、MCP エンドポイントの回数の上限を変更できる手段を提供する。
6. While GROWI が複数のインスタンスで動いているあいだ, the MCP エンドポイント shall 回数を全インスタンスの合計で数える。
7. The MCP エンドポイント shall 1 回のリクエストで、多くとも 1 つのツール呼び出しを実行する。

### Requirement 7: Activity の記録

**Objective:** As a 管理者, I want MCP 経由の利用と設定の変更を監査ログで確かめたい, so that 誰が外部の AI クライアントから wiki を使ったかを追跡できる

#### Acceptance Criteria

1. When 認証済みの MCP クライアントがツールを呼び出したとき, if 監査ログの設定がツール呼び出しを記録対象にしている, the GROWI shall 呼び出した利用者・日時・ツールの名前を Activity として記録する。
2. The GROWI shall ツール呼び出しの Activity を、GROWI の画面での検索やページ閲覧の Activity と区別できる形で記録する。
3. When 認証済みの MCP クライアントが接続確認、またはツールの一覧の取得を行ったとき, the GROWI shall Activity を記録しない。
4. If MCP エンドポイントが認証の失敗でリクエストを拒否したとき, the GROWI shall そのリクエストの Activity を記録しない。
5. When 管理者が MCP 連携の設定を変えたとき, if 監査ログの設定が MCP 連携の設定変更を記録対象にしている, the GROWI shall 変更した管理者と日時を Activity として記録する。
6. The GROWI shall Activity に、アクセストークンの値を記録しない。
7. The 監査ログ shall ツール呼び出しの Activity と MCP 連携の設定変更の Activity を、管理者が種類を指定して絞り込めるようにする。
8. While 監査ログの設定が既定のままのとき, the GROWI shall ツール呼び出しの Activity と MCP 連携の設定変更の Activity を記録しない。

### Requirement 8: 既存の機能と運用への影響

**Objective:** As a 管理者, I want MCP 連携を使わない場合に何も変わらないことを確かめたい, so that 安心してバージョンを上げられる

#### Acceptance Criteria

1. The GROWI shall AI チャットでの全文検索とページ本文取得の結果を、本機能の追加の前後で同じに保つ。
2. The GROWI shall suggest-path の結果を、本機能の追加の前後で同じに保つ。
3. While MCP 連携が一度も有効にされていないあいだ, the GROWI shall MCP サーバーのための部品を読み込まず、起動時のメモリ使用量を増やさない。
4. The GROWI shall 既存の API でのアクセストークンの受け付け方（URL のクエリとリクエストの本文を含む）を、本機能の追加の前後で同じに保つ。
5. If MCP サーバーのための部品の読み込みに失敗したとき, the MCP エンドポイント shall サーバー側のエラーを返し、次のリクエストで読み込みをやり直す。
6. If MCP サーバーのための部品の読み込みに失敗したとき, the GROWI shall MCP エンドポイント以外の機能を動かし続ける。
