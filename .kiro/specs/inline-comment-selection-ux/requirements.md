# Requirements Document

## Project Description (Input)

閲覧者が本文テキストを選択してインラインコメントを作成するUXを、実装済みspec `inline-comment` の設計から見直す amend spec。

## Amend target

対象spec: `inline-comment`（実装完了・master向けマージ済み）

変更対象コンポーネント（design.md の SelectionCapture / InlineCommentForm）:

1. 選択直後にいきなりフル入力フォームを表示する現行フローを、「選択直後は軽量なポップアップ（『コメントする』ボタンのみ）を表示し、選択解除で消える → ボタンクリックで初めて入力フォームへ展開する」という2段階フローに変更する
2. フォームの表示位置を、本文コンテナ下の固定位置（`PageView.tsx` 内、コメント一覧より上）から、選択範囲近傍への浮動配置に変更する
3. メンション入力を、CodeMirrorエディタへの `@` タイプによる補完のみから、フォーム内に明示的な `@` ボタンを追加してユーザーリストを表示できるようにする

参考資料: ユーザー提供の実装UIモックアップ4枚（テキスト選択時のポップアップ→展開フォーム→複数行→末尾コメント一覧への統合表示）

既存のアンカー計算・保存・再アンカリングロジック（クオート/前後文脈/あいまい一致等）、返信・解決トグル、メンション通知連携、共有リンク非公開化には変更を加えない。UI層（SelectionCapture/InlineCommentFormの表示フロー・配置・メンションボタン追加）のみのスコープ。

## Introduction

インラインコメント機能（`inline-comment` spec、実装完了）のうち、本文テキストを選択してからコメントを作成するまでの操作の流れ（選択する → コメントを書き始める操作が現れる → 入力する → 送信する）を、より作り込まれたユーザー体験に見直す。対象は既存実装で選択の監視・作成フォーム表示を担っている部分（`SelectionCapture`/`InlineCommentForm` に相当する表示・操作の流れ）のみであり、アンカーの計算・保存方法、返信・解決管理、メンション通知、共有リンク閲覧者への非公開化など、`inline-comment` spec で既に確定している他の挙動には変更を加えない。

## Boundary Context

- **In scope**: テキストを選択したときに現れる軽量な作成の起点（ボタン）の表示・追随・消去、その起点を選んだときの入力フォームへの展開、入力フォーム内でメンション相手を選ぶための明示的な操作、これらの要素を選択範囲の近くに表示すること
- **Out of scope**: アンカー（選択文字列・前後文脈・おおよその位置）の計算・保存方法、本文編集後の再アンカリングの仕組み、返信の作成、解決／未解決の管理、メンション通知の送信経路、共有リンク閲覧者への非公開化の仕組み自体、`@` に続けて文字を入力したときの既存のメンション補完機能を取り除くこと
- **Adjacent expectations**: この見直しは `inline-comment` spec が既に定めている認可の条件（作成にはログインとページの閲覧権限が必要）と、保存される内容（選択文字列・前後文脈・おおよその位置）をそのまま前提とし、これら自体は変更しない。送信した後にコメント一覧へ反映される仕組みや、ページ再読み込み後のハイライト復元も、`inline-comment` spec の既存の挙動のまま変更しない

## Requirements

### Requirement 1: 選択直後に現れる軽量な作成の起点

**Objective:** As a ページ閲覧者, I want テキストを選択した直後には軽い操作だけが近くに現れてほしい, so that 本文の見た目を大きく妨げずに、コメントを作成するかどうかをその場で判断できる

#### Acceptance Criteria
1. When ログイン済みの閲覧者がページ本文中の空でないテキスト範囲を選択した, the インラインコメント機能 shall 選択範囲の近くに、コメント作成を始めるための一つの操作（作成の起点）を表示する
2. If 選択されたテキストが空である, then インラインコメント機能 shall 作成の起点を表示しない
3. While 作成の起点が表示されており、まだ入力フォームへ展開されていない, the インラインコメント機能 shall ユーザーが選択範囲を変更するたびに、作成の起点の表示位置を新しい選択範囲に合わせて動かす
4. If 入力フォームへ展開される前に選択が解除された, then インラインコメント機能 shall 表示中の作成の起点を消す

### Requirement 2: 作成の起点から入力フォームへの展開

**Objective:** As a ページ閲覧者, I want 作成の起点を選んだときだけ入力フォームが開いてほしい, so that テキストを選んだだけで意図せず入力欄が開いてしまうことがない

#### Acceptance Criteria
1. When ユーザーが表示中の作成の起点を選んだ, the インラインコメント機能 shall その場所をコメント入力フォームに切り替える
2. While 入力フォームが表示されている, the インラインコメント機能 shall 対象の選択範囲の引用文をフォーム内に表示し続ける
3. While 入力フォームが表示されている, the インラインコメント機能 shall 入力欄にカーソルを移動しただけでは、フォームを閉じない
4. When ユーザーが入力フォームを送信またはキャンセルした, the インラインコメント機能 shall 入力フォームを閉じる

### Requirement 3: 入力フォーム内でのメンション相手の選択

**Objective:** As a インラインコメント投稿者, I want 入力中に一覧からメンション相手を選べてほしい, so that 相手のユーザー名を正確に覚えていなくてもメンションできる

#### Acceptance Criteria
1. While 入力フォームが表示されている, the インラインコメント機能 shall メンション相手を選ぶための操作を、本文の入力欄とは別に用意する
2. When ユーザーがメンション相手を選ぶ操作を行った, the インラインコメント機能 shall メンションできるユーザーの一覧を表示する
3. When ユーザーが一覧からユーザーを選んだ, the インラインコメント機能 shall 選ばれたユーザーへのメンションをコメント本文中に挿入する
4. The インラインコメント機能 shall 本文の入力欄に `@` に続けて文字を入力したときの既存のメンション候補表示も、引き続き提供する

### Requirement 4: 作成の起点・入力フォームの表示位置

**Objective:** As a ページ閲覧者, I want 作成の起点や入力フォームが選んだ場所の近くに出てほしい, so that 画面の別の場所を探さずにコメント作成の操作を続けられる

#### Acceptance Criteria
1. The インラインコメント機能 shall 作成の起点と入力フォームを、対象の選択範囲に近い位置に表示する
2. The インラインコメント機能 shall 共有リンク経由の閲覧者向けの画面には、作成の起点・入力フォームのいずれも表示しない（`inline-comment` spec が既に定めている非公開化の方針を引き継ぐ）
