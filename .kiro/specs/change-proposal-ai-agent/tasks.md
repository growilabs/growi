  - core の `ServiceError` のすべての値（`not-found` と `not-open` を含む）を、design の「core の誤りの対応表」の道具の結果の値にして返す。core の誤りの `index` は、AI が送った並びの番号に直す。AI の提案があれば、会話・案・ページの ID だけをログに書く。閲覧範囲が狭いページの名前と ID は、道具の結果にもログにも入れない

  - _Requirements: 4.6, 4.8, 5.7, 5.9, 7.1, 7.2, 7.3, 7.4, 7.11, 7.12, 10.1, 13.2, 13.5, 13.6_

- [ ] 3.5 保留中の案のサービスを作る
  - 依頼した人にだけ返し、それ以外は存在しないのと同じ結果にする。進めるときは、選んだ操作だけを残し、置き場所を選び直した新規作成のパスを作り、閲覧範囲を 3.2 でもう一度確かめ、1.3 の拡張の、状態を条件にした更新（件数で成否を決める）で「作っている途中」（期限つき）にしてから core に作らせる。core には、route から受け取った `trigger` と、保留の記録が持つ元（`basedOn`）をそのまま渡し、ページごとの通知の指定は渡さない
  - 進められるのは、状態が保留中のときと、「作っている途中」の期限が過ぎたときだけにする。保留中の期限が過ぎた案は、TTL 索引が消すのを待たずに、サービスが期限を見て進められないようにする
  - 新しく狭いページが見つかったら作らずに一覧を保存して返す。「確かめた」が無ければ断る。core が断ったら保留に戻し、誤りの `index` をその操作の `key` に直して返す。作れたら Change Proposal の ID を記録し、期限と本文を消す。やめたら以後進められない
  - 選んだ操作だけで作られること、置き場所を選び直したパス、確かめ直し、「確かめた」が無い場合、同時に 2 回進めても 1 つだけ作られること、途中で止まった案を期限のあとで進め直せること、やめた案と期限の切れた案を進められないこと、core が断ったときに保留に戻り `key` が返ること、作ったあとに AI の記録として取れること、元を持つ保留の案を進めると同じ元が core に渡り、見直しなら承認待ちで作られること、進めて作った Change Proposal のページごとの通知の指定が「出す」であることを結合試験で確かめている
  - _Requirements: 3.7, 4.7, 5.8, 7.5, 7.6, 7.7, 7.8, 7.9, 7.12, 10.1, 13.6, 14.4_
