# Implementation Plan

- [ ] 1. サーバー: 管理画面の API を 2 つ足す

- [ ] 1.1 チャンネルの一覧を返す口を足す
  - 管理者の画面が、接続ごとのチャンネルの一覧（名前、識別子、非公開か）を、1 回の呼び出しで取れるようにする
  - chat-integration proxy に届かないときは、エラーの状態にせず、一覧を空にして理由を値として返す
  - 一覧を取るたびに、保存済みの通知先の名前を最新に直す既存の動きが、そのまま起きる
  - 既存の管理者の認可の下に置く
  - 完了の条件: 管理画面の API の試験に、proxy が答えたとき一覧が返ること、届かないとき理由つきの空の一覧が成功の状態で返ること、管理者でないと断られることが加わり、通る
  - _Requirements: 11.14, 11.17, 11.19_
  - _Boundary: admin-router, channel list view_

- [ ] 1.2 通知先を 1 件削除する口を足す
  - 接続・チャンネル・ページのパス条件の組で、通知先を 1 件識別して削除する
  - 値が文字列でないとき（配列やオブジェクトとして解釈される問い合わせ）は、検索の条件に渡さず、不正な入力として断る。長さは、既存の保存と同じ上限で検査する
  - 該当の行が無いときは、見つからないことを返す。別の接続の同じ組の行は消さない
  - 配信イベントが 0 件の通知先を保存できない既存の検査は、変えずに残す
  - 完了の条件: 管理画面の API の試験に、該当の行だけが消えること、別の接続の同じ組の行が残ること、無い行は見つからない扱いになること、必須の値が無い・文字列でないときは不正な入力として断られることが加わり、通る
  - _Requirements: 2.15, 2.16_
  - _Boundary: admin-router, notification-destinations_
  - _Depends: 1.1_

- [ ] 2. クライアント: 土台（通信の口と純粋なロジック）

- [ ] 2.1 (P) 画面から新しい 2 つの口を呼べるようにする
  - チャンネルの一覧の取得と、通知先の削除を、画面の通信の口に足す。一覧の見え方（取得できたか、できなかった理由）を表す型も足す
  - 通知先の削除は、識別の値を問い合わせの形で送る
  - 完了の条件: 型検査が通り、足した 2 つの口が、サーバーの口の URL と方法に一致していることを、口の単位の試験で確かめられる
  - _Requirements: 2.15, 11.14, 11.17_
  - _Boundary: api.ts, types.ts_

- [ ] 2.2 (P) チャンネル権限のフォームの意味を決めるロジックを作る
  - 保存済みの設定から、コマンドごとの編集状態（既定値・すべて・指定したチャンネルのみ・使わない、選んだチャンネル、DM の許可）を作る。保存された設定が無いコマンドは「既定値」にする
  - 「既定値」の挙動（許可する／許可しない）を、コマンドの性質（書き込みを伴うか）から決める。コマンド名では分岐しない
  - 編集状態から、保存する形を作る。「既定値」のコマンドは設定を作らない。ただし、DM を許す設定が要るコマンドで DM を許したときは、チャンネルでの挙動を変えない設定を 1 つ作る
  - 「指定したチャンネルのみ」でチャンネルが 0 件のコマンドを、保存できない誤りとして返す
  - 「変更があるか」は、保存する形どうしの比較で決める。選んだチャンネルの順序・重複、保存の形に出ない欄だけの違いは、変更として数えない
  - 完了の条件: 隣の試験が、行が無いコマンドが既定値になること／既定値が保存の形に出ないこと／0 件の指定が誤りになること／DM だけを許す設定が既定の挙動に等しいチャンネル設定で出ること／順序と重複を無視すること／選択を変えて元に戻すと変更なしになること／全コマンドで既定値の分類が「書き込みを伴うか」だけで決まることを確かめ、通る
  - _Requirements: 11.9, 11.10, 11.11, 11.12, 11.13, 11.16, 11.18, 11.20, 16.4_
  - _Boundary: permission-form_

- [ ] 2.3 (P) チャンネルの選択の行を組み立てるロジックを作る
  - チャンネルの一覧と選択済みの識別子と絞り込みの文字から、表示する行を作る
  - 絞り込みは、名前または識別子への、大文字小文字を区別しない部分一致にする
  - 選択済みなのに一覧に無い識別子は、絞り込みに関わらず、先頭の別の種類の行として出す
  - 完了の条件: 隣の試験が、絞り込みが名前と識別子の両方に効くこと、一覧に無い選択済みの識別子が絞り込みに関わらず先頭に出ることを確かめ、通る
  - _Requirements: 11.14, 11.19_
  - _Boundary: channel-picker-rows_

- [ ] 2.4 (P) 接続の並び順を決めるロジックを作る
  - 使用中の接続を先、切断済みを後ろに並べる。同じ状態の中は、元の順を保つ
  - 完了の条件: 隣の試験が、切断済みが最後になること、同じ状態の中の順が変わらないことを確かめ、通る
  - _Requirements: 16.3_
  - _Boundary: sort-relations_

- [ ] 3. クライアント: 表示言語ごとの文言の hook

- [ ] 3.1 状態と「できること」の表の言葉の hook を作る
  - 接続の状態（使用中・切断済み・接続が切れている）と接続の健全性、サービス名、機能の名前、対応の程度を、管理者に意味の分かる言葉にする
  - 既知の値ごとに、文字列で書いたキーで文言を引く。知らない値は、受け取った値をそのまま返す
  - サービス名は固有名として、5 言語で同じ値にする
  - 5 言語（`en_US`・`ja_JP`・`zh_CN`・`fr_FR`・`ko_KR`）の管理画面の文言に、同時にキーを足す
  - 完了の条件: hook の試験が、既知の値がそれぞれのキーに対応すること、知らない値が生のまま返ることを確かめ、通る。5 言語に同じキーがある
  - _Requirements: 1.23, 1.24, 9.29, 16.9_
  - _Boundary: use-status-labels, use-capability-labels, admin.json_

- [ ] 3.2 接続の追加の失敗の知らせの hook を作る
  - 失敗した結果（登録コードの期限切れ、所有を確認できない、proxy に接続できない、すでに接続済み、識別子がすでにある、暗号化キー未設定）ごとに、見出しと、次に確認・実行する手順の並びを返す
  - 所有を確認できないときは、原因を断定せず、確認点 3 つ（到達できる URL、起動と証明書、許可リスト）を手順にする。proxy が返した詳細は使わない
  - proxy に接続できないときは、失敗の種類を補足として添える
  - すでに接続済みのときは、一覧の確認の案内に加えて、チャットサービスでの登録の解除（`unregister`）の手順を常に添える。手順の文は、「一覧に有効な接続が無い場合は」と条件を自分で述べる
  - 追加の結果の型を、この機能の追加の画面の型の置き場に移す
  - 5 言語の管理画面の文言に、同時にキーを足す
  - 完了の条件: hook の試験が、6 つの失敗それぞれの見出しと手順、すでに接続済みで `unregister` の手順が常に出ること、所有を確認できないときに詳細を使わないことを確かめ、通る
  - _Requirements: 9.18, 9.19, 9.20, 9.21, 9.22, 9.23, 16.9_
  - _Boundary: use-pairing-failure-view, pairing types, admin.json_
  - _Depends: 3.1_

- [ ] 3.3 設定の保存結果の文言の hook を作る
  - 保存の成功、保存はできたが proxy への即時の反映に失敗した場合、保存の失敗（同時に保存された、入力が不正、接続が見つからない、それ以外）の文を返す
  - どの文も、内部の用語（設定の版、proxy）を含めない。失敗の文は、管理者が取れる操作（読み込み直して、もう一度）を含める
  - サーバーのエラーの英語のメッセージは使わず、エラーの種類から文を引く
  - 5 言語の管理画面の文言に、同時にキーを足す
  - 完了の条件: hook の試験が、成功／反映の遅れ／同時に保存された／知らない種類の失敗のそれぞれで、期待のキーが返ることを確かめ、通る
  - _Requirements: 16.6, 16.7, 16.8, 16.9_
  - _Boundary: use-save-result-message, admin.json_
  - _Depends: 3.2_

- [ ] 3.4 チャンネルの表示の hook を作る
  - チャンネルを「#名前 (識別子)」の形で表し、非公開のものにはその言語の印を付ける。印は、英語では今の表示に合わせ、ほかの言語はその言語の「非公開」にする
  - 名前と識別子は翻訳しない
  - 5 言語の管理画面の文言に、同時にキーを足す
  - 完了の条件: hook の試験が、公開のチャンネルに印が付かないこと、非公開のときだけ印のキーが付くことを確かめ、通る
  - _Requirements: 11.15, 16.9, 16.10_
  - _Boundary: use-describe-channel, admin.json_
  - _Depends: 3.3_

- [ ] 4. クライアント: 部品

- [ ] 4.1 サービスに依存しないチャンネルの選択のモーダルを作る
  - 渡されたチャンネルの一覧を、絞り込みながらチェックして選べる。選択数を示す
  - 選択は下書きで持ち、「決定」で選んだ識別子の並びを返し、「キャンセル」と閉じる操作で捨てる。開くたびに、渡された選択から下書きを作り直す
  - 一覧に無い選択済みの識別子は、先頭に「一覧にない」の印つきで出し、チェックを外せる
  - 部品は、サービス名にも、権限という用途にも依存しない（平らなデータだけを受け取る）
  - 選択数の文は、複数形のキーも含めて 5 言語に足す
  - 完了の条件: 部品の試験が、絞り込んでチェックして決定すると識別子の並びが返ること、キャンセルで下書きが捨てられること、一覧に無い行を外せることを確かめ、通る
  - _Requirements: 11.14, 11.15, 11.19, 16.9_
  - _Boundary: ChannelPickerModal, channel-picker barrel, admin.json_
  - _Depends: 2.3, 3.4_

- [ ] 4.2 権限の行を作る
  - コマンド名（翻訳しない）と、4 つの選択肢の選択欄を並べる。「既定値」の項目には、そのコマンドの既定の挙動を添える（読み取り系は「既定値（すべてのチャンネルで許可）」、書き込み系は「既定値（許可しない）」）
  - 「指定したチャンネルのみ」のとき、選ばれたチャンネルを並べ（一覧に無い識別子には印を付ける）、「チャンネルを選ぶ」でモーダルを開く
  - チャンネルの一覧が取れていないとき: 選択欄はすべて選べるままにし、「チャンネルを選ぶ」だけを押せなくして、行の中に、選べない理由と対処を示す。名前が引けないので、識別子だけを示し、「一覧にない」の印は付けない
  - 書き込みでページを作りうるコマンドの注意書きと、DM の欄は、今のまま残す
  - 5 言語の管理画面の文言に、同時にキーを足す
  - 完了の条件: 部品の試験が、既定値の項目の文言が書き込み系と読み取り系で変わること、一覧が取れないとき「指定したチャンネルのみ」は選べるが「チャンネルを選ぶ」は押せず理由が出ること、一覧に無い識別子に印が付くことを確かめ、通る
  - _Requirements: 11.9, 11.10, 11.12, 11.17, 11.19, 16.9, 16.10_
  - _Boundary: PermissionRow, admin.json_
  - _Depends: 2.2, 4.1_

- [ ] 4.3 権限の節とフォームを作り、保存まで通す
  - 設定とチャンネルの一覧を取り、一覧が取れなかったときは、取れなかったことと理由を節の上部に示す。チャンネルの一覧は、画面に戻ったときに取り直さない
  - 保存済みの内容から作ったフォームと比べて、変更が無いあいだは保存を押せなくし、変更があるあいだは「保存していない変更があります」を示す
  - 保存を押したとき、指定したチャンネルが 0 件の行があれば、その行にエラーを示して送らない。一覧が取れていないときは、「選んでください」ではなく、選べない理由のエラーを示す
  - 保存した結果は、成功・反映の遅れ・失敗の文で示す。「設定の版」の表示はなくす。成功したら、保存後の内容でフォームを組み直す
  - 「既定値」のコマンドの設定は送らない。一覧が取れていなくても、保存済みの指定チャンネルは、保存で変わらない
  - 5 言語の管理画面の文言に、同時にキーを足す
  - 完了の条件: 部品の試験が、初期は保存を押せないこと、変更で押せて未保存の表示が出ること、変更を戻すと元に戻ること、0 件の指定で保存が止まりエラーが出ること、既定値のコマンドの設定が送られないこと、一覧が取れないときに保存済みの指定チャンネルが保存で変わらないことを確かめ、通る
  - _Requirements: 11.13, 11.16, 11.17, 11.18, 11.20, 16.4, 16.5, 16.6, 16.7, 16.8, 16.9_
  - _Boundary: ChannelPermissionsSection, ChannelPermissionsForm, admin.json_
  - _Depends: 2.1, 3.3, 4.2_

- [ ] 4.4 通知先の節を、削除と検査と文言に対応させる
  - 追加の側の見た目と選び方は変えない。文言を 5 言語の文言に置き換える。配信イベントの名前は、既存の通知設定の画面と同じ文言を使う。チャンネルの表示は、チャンネルの表示の hook にそろえる
  - 追加は、チャンネルが未選択か、配信イベントが 0 件のあいだ押せない。0 件のあいだ、「配信イベントを 1 つ以上選んでください」を示す
  - 各行に「削除」を置く。押すと削除の口を呼び、成功したら一覧を読み直して知らせる。見つからないという答えも、すでに無いものとして読み直す。確認のモーダルは設けない
  - 保存の結果の文言は、内部の用語を含めない
  - 5 言語の管理画面の文言に、同時にキーを足す。この部品を扱う既存の試験の、英語の文言への依存を直す
  - 完了の条件: 部品の試験が、配信イベントが 0 件で追加を押せず理由が出ること、削除の操作で削除の口が呼ばれて一覧が読み直されること、見つからない答えでも一覧が読み直されることを確かめ、通る
  - _Requirements: 2.15, 2.17, 16.6, 16.9, 16.10_
  - _Boundary: NotificationDestinationsSection, admin.json_
  - _Depends: 1.2, 2.1, 3.4_

- [ ] 4.5 接続の追加の入力の手がかり・初期値・失敗の知らせを作る
  - 4 つの入力欄すべてに、例または説明（欄の中の例と、欄の下の補足）を付ける
  - 「この GROWI の URL」と「表示名」に、この GROWI のサイト URL とアプリ名を、書き換えられる初期値として入れる。サイト URL が未設定のときは、空にして例を示す
  - 結果が成功以外のとき、失敗の知らせを、接続の追加のモーダルの中に、見出しと手順の並びで示し、モーダルは閉じない。次の送信を始めるとき、またはモーダルを閉じるときに消す。入力を直している間は消さない
  - 通信そのものの失敗など、結果にならない失敗は、汎用の「もう一度試す」を同じ場所に示す
  - 成功したときは、閉じて一覧を読み直し、内部の用語を含まない言葉で知らせる。置き換えた古い文言の部品は消す
  - 5 言語の管理画面の文言に、同時にキーを足す。この部品を扱う既存の試験を直す
  - 完了の条件: 部品の試験が、サイト URL とアプリ名が初期値に入ること、サイト URL 未設定なら空で例が出ること、失敗でアラートが出てモーダルが閉じないこと、再送信でアラートが消えることを確かめ、通る
  - _Requirements: 9.14, 9.15, 9.16, 9.17, 9.18, 9.19, 9.20, 9.21, 9.22, 9.23, 16.9_
  - _Boundary: PairingSection, PairingForm, admin.json_
  - _Depends: 3.2_

- [ ] 4.6 切断の確認のモーダルを作る
  - 切断を始めると、対象の接続の名前をタイトルに入れたモーダルを開き、確認するまで切断しない
  - 本文を「削除されるもの」「残るもの」「注意」の 3 つに分けて示す。削除されるもの: チャンネル権限、通知先、署名用の鍵、元に戻せないこと。残るもの: ユーザーのアカウント連携、その保持日数、同じワークスペースを再接続すると引き継がれること。注意: GROWI 側だけに反映されること、チャットサービス側の登録は残ること、再接続するには先に登録を解除する必要があること。件数は出さない
  - 実行中は、閉じる・取り消しを押せなくする。成功したらモーダルを閉じて一覧を読み直し、失敗したらモーダルの中にアラートで示す
  - 5 言語の管理画面の文言に、同時にキーを足す
  - 完了の条件: 部品の試験が、タイトルに接続の名前が出ること、確認の操作まで切断の口が呼ばれないこと、3 つの見出しが出ること、失敗でモーダルの中にアラートが出ることを確かめ、通る
  - _Requirements: 9.26, 9.27, 16.9_
  - _Boundary: DisconnectModal, admin.json_
  - _Depends: 3.4_

- [ ] 4.7 「できること」の表を、意味の分かる言葉で出す
  - サービス・機能・対応の程度を、言葉の hook で置き換えて出す。「代わりの方法」は、proxy が返した文をそのまま出す
  - proxy が返したサービス・機能の全行を出す。知らない値の行も、生の値のまま出し、欠落させない
  - 表の見出しなどの文言を、5 言語の文言にする
  - 完了の条件: 部品の試験が、既知の値が言葉で出ること、知らない機能・程度・サービスの行が生の値で出て欠落しないことを確かめ、通る
  - _Requirements: 1.23, 1.24, 16.9_
  - _Boundary: CapabilityReportTable, admin.json_
  - _Depends: 3.1_

- [ ] 4.8 接続のカードと、折りたたみを作る
  - カードの上部に、名前、サービス名、状態、接続状態、「できること」の表を出す。状態と接続状態は、言葉の hook で置き換える。接続が切れている説明の文は、切断の操作が折りたたみの中に入ることに合わせて、5 言語すべてで、「この接続の設定を開き、「切断」を押すか、もう一度ペアリングする」という案内に直す。切断のボタンの名前は、その言語の「切断」にそろえる
  - 使用中のカードは、チャンネル権限・通知先・切断の操作を 1 つの折りたたみにまとめ、初期は閉じる。初めて開いたときに初めて描き、そのあとは閉じても描いたままにする。初めて開くまで、権限と通知先の取得は走らない
  - 切断済みのカードは折りたたみを持たず、消える日と、再接続の手順（チャットサービスで登録を解除し、新しい登録コードで接続を追加する）を示す
  - 切断の操作は、モーダルを開く

## Implementation Notes

- **試験の回し方**: app の chat-integration の試験は、`MONGO_URI='mongodb://mongo:27017/growi_test_chat?replicaSet=rs0'` を付けて、1 ファイルずつ回す（`chat-integration-agent` の記録と同じ。共有の MongoDB は、全体を並列で回すと接続が切れる）。app の型検査と試験の前に、依存の build（`pnpm turbo run build --filter @growi/app^...`）が要ることがある。
- **文言のキーの持ち主**: 文言のキーは、使う部品の作業と同じ作業で、5 言語に同時に足す。同じ 5 つの `admin.json` を触るので、文言を足す作業は、順に行う（`(P)` を付けない）。
- **既存の試験**: 既存の部品を直接書き換える作業（4.4、4.5）は、その部品の既存の試験の、英語の文言への依存を、同じ作業で直す。新しい部品に置き換える作業は、古い実装が残るあいだ古い試験を通し続け、5.1 で古い試験の項目を移して取り除く。
- **文言の hook の試験**: 文言の hook の試験は、キーをそのまま返す `t` の差し替えを使う（既存の試験と同じ）。部品を、実際の言葉で試験しない。
- **書き戻しの順番**: 7 は、`chat-integration-agent` のタスク 7 が済んでから行う（7.1）。
