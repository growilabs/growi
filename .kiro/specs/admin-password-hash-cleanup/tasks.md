# Implementation Plan

- [ ] 1. 共有コアから中断を撤廃する
- [ ] 1.1 クリーンアップ本体の中断分岐と報告用集計を取り除く
  - 未移行ユーザーの人数を理由に処理を打ち切る分岐を削除し、両形式を持つユーザーの旧形式資格情報を常に削除する
  - 結果を削除件数のみに縮約する。中断の有無を表す値と、削除前に別クエリで取得していた未移行者の内訳を除去する
  - 既存の統合テストのうち「中断する」ことを主張するものを反転させ、同じ条件で両形式ユーザーが削除され、未移行ユーザーの資格情報が無傷で残ることを主張する形にする
  - 連続 2 回実行しても 2 回目が削除件数 0 で正常終了することを主張するテストを追加する
  - 反転させたテストが、中断分岐を一時的に戻すと失敗することを確認する
  - 先行仕様の中断規則に、本仕様がこれを改訂した旨と両経路に適用される旨を追記し、2 つの仕様が矛盾しない状態にする
  - 完了状態: アクティブな未移行ユーザーを含む fixture に対して統合テストが緑になり、未移行ユーザーの旧形式資格情報がテスト後も残存している
  - _Requirements: 2.1, 2.9, 3.1, 3.2, 7.1, 7.2_
  - _Boundary: runPasswordHashCleanup_

- [ ] 1.2 コマンドライン入口を新しい結果に合わせる
  - 終了コードの決定から中断の概念を外し、例外時のみ非ゼロとする
  - 削除件数に加えて未移行者の内訳を分布集計から取得し、従来どおり構造化ログへ出力する。クリーンアップ本体はこの集計を持たなくなるため、入口側が明示的に呼ぶ
  - 完了状態: アクティブな未移行ユーザーが存在する状態でコマンドラインから実行しても終了コードが 0 になり、削除件数と未移行者の内訳の両方がログに出る
  - _Requirements: 3.3, 7.2_
  - _Boundary: CLI entry_

- [ ] 2. (P) 分布集計を単一パスの集約に置き換える
  - 4 状態とアクティブ内訳を 1 本の集約で算出し、各区分の絞り込みには既存の分類フィルタをそのまま渡す。分類規則を集約式として書き直さない
  - 呼び出し側から渡される絞り込み条件は集約の前段に置き、各区分に重複させない
  - 件数ゼロの区分が結果を返さないことを考慮し、ゼロとして読む
  - 既存の分布テストに加え、集約の結果が同じフィルタによる逐次カウントと全区分で一致することを確認する
  - 完了状態: 分布の全カウンタが単一の問い合わせから得られ、各区分の合計が対象ユーザー総数に一致する
  - _Requirements: 1.1, 1.2_
  - _Boundary: countPasswordHashFormatDistribution_

- [ ] 3. 未移行者一覧の走査を限定する
- [ ] 3.1 (P) 旧形式保持者だけを対象とする部分インデックスを宣言する
  - 最終サインインの降順を支える索引を、旧形式資格情報を持つ文書に限定して宣言する
  - 既存の索引宣言と同じ場所・同じ方式で定義する
  - 完了状態: 未移行者一覧の問い合わせが、全件走査ではなくこの索引を用いた走査として計画される
  - _Requirements: 4.3_
  - _Boundary: user schema_

- [ ] 3.2 索引導入後も一覧の契約が変わらないことを確かめる
  - ページングが総数を正しく報告し、ページをまたいで重複・欠落が出ないことを確認する
  - 各行がユーザー名・メールアドレス・最終サインイン・外部アカウントの有無を持つことを確認する
  - 一度もサインインしていないユーザーが末尾に来る順序が維持されることを確認する
  - 上限を超えるページサイズが要求されたとき、上限までに抑えられることを確認する
  - 完了状態: 一覧の統合テストが索引導入の前後で同じ結果を返す
  - _Depends: 3.1_
  - _Requirements: 4.1, 4.2, 4.7_
  - _Boundary: listPasswordHashUnmigratedUsers_

- [ ] 4. 管理 API から中断の痕跡を取り除く
  - 中断を表す応答分岐を削除する。業務上の理由で失敗する経路が無くなるため、残る失敗はシステム障害のみとなる
  - 共有の応答型から実行可否を表すフラグを除去する。クライアントは分布から同じ判断ができる。**この型変更は管理画面側を直ちに壊すため、画面の追従は 5.1 で行う。型変更と画面修正が揃って初めてビルドが通る**
  - 旧形式資格情報がどこにも残っていないことを表す判定は応答に残す。これは自明でない規則であり、過去にクライアント側での誤導出が不具合を生んでいる
  - API 定義から、廃止した応答の記載を削除する
  - 既存の API テストのうち中断応答を主張するものを反転させ、未移行者がいる状態でも成功応答が返ることを主張する形にする
  - 3 経路すべてについて、管理者以外からの要求が拒否され情報が漏れないこと、および実行が監査記録に実行者とともに残ることを、既存テストで引き続き満たすことを確認する
  - 完了状態: アクティブな未移行ユーザーが存在する状態でクリーンアップを要求すると削除件数つきの成功応答が返り、監査記録に実行者が帰属している
  - _Depends: 1.1_
  - _Requirements: 1.5, 2.4, 2.5, 2.6, 2.7, 3.1, 4.8_
  - _Boundary: API handlers, shared response contract_

- [ ] 5. 管理画面を中断のない前提に合わせる
- [ ] 5.1 状態表示を 2 状態に縮約し、未移行者の扱いを正しく伝える
  - 廃止された実行可否フラグへの依存を取り除き、削除対象の有無だけで実行操作の可否を決める
  - 中断を前提とした表示分岐を削除し、削除対象がある状態と削除対象がない状態の 2 つに整理する
  - 未移行ユーザーが存在する場合に、それらがクリーンアップの影響を受けず資格情報が旧形式のまま残ることを常時提示する。従来の「処理を阻んでいる」という枠づけを置き換える
  - 外部プロバイダ経由でのみ認証するユーザーや長命なセッションを持つユーザーは使い続けるだけでは移行しない、という説明を維持する
  - 削除対象が存在しないときは実行操作を提供しない
  - 対応する文言を 5 言語すべてに用意し、廃止した文言を削除する。暗号アルゴリズム名とコマンドライン手順は書かない
  - 既存のコンポーネントテストのうち中断表示を主張するものを反転させる
  - 完了状態: 未移行者だけが存在するインスタンスで、パネルが「削除対象なし」と未移行者への説明を示し、実行ボタンが押せない状態で描画される
  - 完了状態: タスク 4 で生じた型の不整合がここで解消し、パッケージの型検査とビルドが通る。廃止した実行可否フラグへの参照がリポジトリ内に 1 つも残っていない
  - _Depends: 4_
  - _Requirements: 2.8, 3.4, 3.5, 5.3, 6.3, 6.4_
  - _Boundary: PasswordHashMigration, locales_

- [ ] 5.2 (P) 一覧の開閉操作をラベルで特定できるようにする
  - 開閉ボタン内の装飾アイコンを支援技術から隠し、ボタンのアクセシブル名にアイコン文字列が連結されないようにする
  - リポジトリ内の既存の同種の記述に合わせる
  - 現在失敗している一覧のコンポーネントテストが、この修正によって通ることを確認する
  - 一覧の取得失敗時に、空の一覧ではなく失敗が提示されることを引き続き満たすことを確認する
  - 完了状態: 一覧のコンポーネントテストが全件通り、開閉ボタンが表示文言だけで特定できる
  - _Requirements: 4.4, 4.5, 4.6_
  - _Boundary: UnmigratedUserList_

- [ ] 6. 文言に暗号アルゴリズム名とコマンドライン手順が混入しないことを検査する
  - 全言語の当該文言群を走査し、旧形式・新形式いずれの暗号アルゴリズム名も含まれないことを主張する
  - 同様に、コマンドライン手順の名称が含まれないことを主張する
  - 検査対象の言語が増えたときに自動的に含まれるよう、言語一覧を固定で列挙しない
  - 禁止語を一時的に文言へ混入させると検査が失敗することを確認する
  - 完了状態: 禁止語を含む文言を追加すると検査が失敗し、現在の文言では通る
  - _Depends: 5.1_
  - _Requirements: 6.1, 6.2_
  - _Boundary: locale disclosure guard_

- [ ] 7. パネルの生存期間と失敗時の挙動を通しで確認する
  - 旧形式資格情報がどこにも残っていない状態でパネルが現れないことを確認する
  - 状態の取得が完了していない間もパネルが現れないことを確認する
  - 状態の取得に失敗したとき、ゼロ件の分布表ではなく失敗が提示されることを確認する
  - 実行前に取り消し不能である旨と、移行前のビルドで既存パスワードが使えなくなることが提示され、承諾するまで実行できないことを確認する
  - 実行後に画面を再読み込みせずに分布が更新されることを確認する
  - 完了状態: 一連のコンポーネントテストが緑で、クリーンアップ成功後に分布が再取得されている
  - _Depends: 4, 5.1_
  - _Requirements: 1.3, 1.4, 2.2, 2.3, 5.1, 5.2_
