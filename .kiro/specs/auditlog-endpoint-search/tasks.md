# Implementation Plan

- [ ] 1. 一覧 API で URL による絞り込みができる
- [ ] 1.1 絞り込み条件の組み立てが、URL をパス部分の完全一致の条件に変換できる
  - 共有の一覧の絞り込み条件の型（`ISearchFilter`）に、URL（パス部分）の配列の項目を足す。この型の拡張はこのタスクが担当する
  - 選んだパスのいずれかと等しい値、または「パスの直後に `?` が続く値」に一致する条件を組み立てる純粋関数を、一覧とエクスポートのジョブが共有できる activity のサービス（`server/service/activity`）に置き、barrel から公開する。前方一致に使う値は、正規表現の記号をエスケープしてから `?` を付ける
  - 一覧の絞り込み条件の組み立ては、この関数の条件を AND の要素として足し、ユーザー名・アクション・期間の条件と AND で結合する。トップレベルの OR は使わない
  - ユーザー名と URL の条件は、配列で、空でなく、要素がすべて文字列のときだけ付ける。既存のユーザー名の判定も同じ形に直し、文字列が来ても例外を投げないようにする
  - 単体テストで、OR の形・エスケープ・大文字小文字の区別・AND での結合・不正な値（空、未指定、文字列、文字列以外の要素）を無視することが確かめられ、通る
  - _Requirements: 1.3, 2.1, 2.2, 2.3, 2.4, 3.8, 5.2_
- [ ] 1.2 一覧 API の 2 経路が URL の条件を受け取り、実際のデータベースで正しく絞り込める
  - GET と POST の両経路で、検索条件の URL の項目を絞り込み条件の組み立てに受け渡す
  - OpenAPI の検索条件の説明に URL の項目を足す
  - 実際の MongoDB を使う integ テストで、`/_api/v3/page` を選ぶと `/_api/v3/page` と `/_api/v3/page?x=1` が返り、`/_api/v3/pages` と `/_API/v3/page` は返らないこと、`(` や `.` を含むパスも一致することが確かめられ、通る（Prisma の `startsWith` がエスケープしない振る舞いを固定する）
  - _Requirements: 1.3, 2.1, 2.2, 2.3, 2.4_

- [ ] 2. 検索欄の判断ロジックと文言がそろっている
- [ ] 2.1 (P) 検索対象の種類の表と、送る入力の決定・候補を出すかの判定・候補一覧の組み立てができる
  - 検索対象の種類（すべて・ユーザー・URL）と、それぞれが候補を取る種類・選択肢の文言キー・ボタンの文言キーを 1 か所の表で宣言する。ボタンの文言キーは、「すべて」が「絞り込みを選択」、それ以外はその種類の選択肢と同じキーにする。表の順序が選択肢と候補のグループの順序になる。文言キーの名前は 2.2 のキー一覧に合わせる
  - 候補 API の `q` の上限（100 文字）を、画面とサーバーで共有する定数として型の定義のファイル（`interfaces/activity.ts`）に足す。この定数の追加はこのタスクが担当する
  - 送る入力を決める関数を作る。入力から最初の `?` 以降を除き、前後の空白を除いて検索文字列を作る。検索文字列が 2 文字未満なら空にし、それ以外は先頭 100 文字（上の定数）に切る
  - 古い応答の判定を 1 つの関数にまとめ、比べる両側を上の関数で正規化する。候補ごとの除外（古い候補と選択済みの値を除く）と、候補一覧のグループの組み立て（失敗のグループと一致なしのグループは新しいときだけ出す）の両方がこの判定を使う
  - 候補 API が今の入力に対して 1 件も返さなかったときは、一致なしのグループを 1 つだけ返す。取得待ち・古い結果・2 文字未満・返った候補がすべて選択済みのときは返さない
  - 単体テストで、送る入力の決定（`?` 以降の除去、`?` を除くと 2 文字未満になる入力、2 文字未満・前後の空白・100 文字での切り出し、クエリ文字列を含めると 100 文字を超えるがパス部分は 100 文字以内の入力）、100 文字を超えて入力を続けても・`?` 以降だけを書き換えても新しいと判定されること、古い候補・選択済みの値の除外、種類が違えば同じ値でも出すこと、種類の順のグループ、0 件の種類はグループにならないこと、失敗したときは失敗のグループ 1 つだけになること、古い入力に対する失敗のグループは出さないこと、一致なしのグループの出る条件と出ない条件、ボタンの文言キーが確かめられ、通る
  - 1.x とは独立して進められる（型を共有しない。`interfaces/activity.ts` には 1.1 と別の定義を足すだけ）
  - _Requirements: 1.1, 1.5, 1.6, 1.7, 3.2, 3.3, 3.4, 3.7, 3.10, 4.1, 4.3_
  - _Boundary: search-scopes, search-suggestion-options_
