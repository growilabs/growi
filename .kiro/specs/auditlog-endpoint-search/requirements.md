# Requirements Document

## Introduction

管理画面の監査ログ（`/admin/audit-log`）で操作の痕跡を調べる管理者が、特定の URL（activity に記録された endpoint）に対する操作だけを一覧に絞り込めるようにする。現在の監査ログ一覧はユーザー名・期間・アクションでしか絞り込めず、URL で絞り込む手段がない。

本機能では、デザイン（Figma: https://www.figma.com/design/ZiEcjZ8sYt6YvowboA5Um6/GROWI-v7?node-id=6680-8235 、 https://www.figma.com/design/ZiEcjZ8sYt6YvowboA5Um6/GROWI-v7?node-id=6684-13348 ）に従い、ユーザーと URL を 1 つの検索欄で検索できるようにする。管理者は検索欄に入力して候補を出し、候補から選んだ値で一覧を絞り込む。検索欄の右側の「絞り込みを選択」で、検索対象を「すべて」「ユーザー」「URL」から切り替えられる。

本書における用語は次のとおり。

- **監査ログビューア**: 監査ログ画面で activity 一覧と絞り込みの操作を提供する UI
- **検索欄**: 監査ログビューアのフィルター行にある、ユーザーと URL を検索する 1 つの入力欄
- **URL**: activity に記録された endpoint。記録された値はクエリ文字列（`?` 以降）を含みうる
- **パス部分**: URL からクエリ文字列（`?` 以降）を除いた部分

## Boundary Context

- **In scope**:
  - ユーザーと URL を 1 つにまとめた検索欄と、「絞り込みを選択」による検索対象の切り替え（既存のユーザー名の絞り込み欄を置き換える）
  - URL の候補表示と、候補から選んだ URL による一覧の絞り込み
  - 候補を取得できなかった場合の表示
  - 追加する文言の多言語対応（en / ja / ko / zh / fr の全ロケール）
  - `.kiro/specs/activity-log-snapshot/design.md` のうち、依存先 `findSnapshotUsernamesByUsernameRegex` の説明を今のコードに合わせる修正（`activity-log-snapshot` の契約は変えない）
- **Out of scope**:
  - IP アドレスの検索（後続のタスクで扱う。「絞り込みを選択」の選択肢にも出さない）
  - 監査ログのエクスポートのモーダルの絞り込み（ユーザー名・期間・アクションのまま変えない）
  - URL を貼り付けたときの正規化。一覧の URL 列からコピーした値（クエリ文字列を含む）は扱えるが、開発者ツールなどからコピーしたオリジン付きの完全な URL は対象外。また、候補 API が受け付ける入力は 100 文字までなので、クエリ文字列を含めて 100 文字を超える値は、パス部分が短くても候補が出ない
  - デコード済みの形の入力を、記録された形に変換すること。記録された URL はパーセントエンコードされた形なので、デコード済みの形（`/日本語ページ` など）で入力すると候補が出ない。日本語のパスが記録されるのは、主にページの表示の記録（`PAGE_VIEW` / `PAGE_NOT_FOUND` など。どの記録グループにも入っていない）を `AUDIT_LOG_ADDITIONAL_ACTIONS` で足した場合
  - 候補を選ばずに入力した文字列による絞り込み（自由入力）
- **Adjacent expectations**:
  - URL 候補の検索は、既存の候補 API の振る舞いを前提とする。全文検索サーバーが止まっていても、データベースで候補を検索して返す。入力に前方一致し、大文字小文字を区別し、あいまい一致は使わない。入力のクエリ文字列（`?` 以降）は捨てて検索する。候補はパス部分の単位で返る
  - データベースでの URL 候補の検索は、migration で作られる endpoint のインデックスを使う
  - 全文検索サーバーが使えず、データベースでの候補の検索も失敗した場合（時間切れなど）、候補 API は空の候補を返す。この場合、本機能では「該当なし」と同じ表示になる（既知の制約。サーバーのログで追う）
  - ユーザー候補の検索の振る舞い（あいまい一致、Active / Inactive の区別）は既存のまま変えない
  - 期間・アクションの絞り込み、エクスポート、一覧の各列の表示は既存のまま変えない

## Requirements

### Requirement 1: URL を候補から選んで一覧を絞り込む

**Objective:** 管理者として、URL を候補から選んで監査ログ一覧を絞り込みたい。そうすることで、特定の URL に対する操作だけを調べられる。

#### Acceptance Criteria

1. When 管理者が検索対象が「すべて」または「URL」の状態で検索欄に文字を入力する, the 監査ログビューア shall 入力に前方一致する URL の候補を表示する。
2. When 管理者が URL の候補を選ぶ, the 監査ログビューア shall その URL を選択済みの値として検索欄に表示し、一覧をその URL の記録に絞り込む。
3. The 監査ログビューア shall URL を複数選べるようにし、選んだ URL のいずれかに一致する記録を一覧に表示する。
4. When 管理者が選択済みの URL を外す, the 監査ログビューア shall その URL を一覧の絞り込み条件から外す。
5. The 監査ログビューア shall 候補から選んだ値だけを絞り込み条件として扱い、候補を選ばずに入力した文字列では一覧を絞り込まない。
6. While 検索欄に文字が入力されていない, the 監査ログビューア shall 候補を表示しない。
7. While 検索欄の入力の前後の空白を除いた長さが 100 文字を超えている, the 監査ログビューア shall 候補を取得せず、候補も取得できなかったことの表示も出さない。

### Requirement 2: URL の一致の仕方

**Objective:** 管理者として、選んだ URL に対する記録だけを漏れなく一覧に出したい。そうすることで、クエリ文字列の違いで記録を見落としたり、別の URL の記録が混ざったりしない。

#### Acceptance Criteria

1. When 管理者が URL で一覧を絞り込む, the 監査ログビューア shall 記録された URL のパス部分が選んだ URL と完全に一致する記録を表示する。
2. When 記録された URL がクエリ文字列を含む, the 監査ログビューア shall クエリ文字列を除いたパス部分で一致を判定する。
3. The 監査ログビューア shall 選んだ URL で始まるだけの別の URL（例: `/_api/v3/page` を選んだときの `/_api/v3/pages`）の記録を一覧に含めない。
4. The 監査ログビューア shall URL の一致を判定するときに大文字と小文字を区別する。

### Requirement 3: ユーザーと URL を 1 つの検索欄で検索する

**Objective:** 管理者として、ユーザーと URL を 1 つの検索欄で検索したい。そうすることで、検索対象ごとに入力欄を探さずに絞り込める。

#### Acceptance Criteria

1. The 監査ログビューア shall ユーザーと URL を 1 つの検索欄で検索できるようにする。
2. The 監査ログビューア shall 「絞り込みを選択」で検索対象を「すべて」「ユーザー」「URL」から選べるようにし、初期状態を「すべて」にする。
3. While 検索対象が「すべて」, when 管理者が検索欄に文字を入力する, the 監査ログビューア shall ユーザーの候補と URL の候補を、種類ごとの見出しを付けて 1 つの候補一覧に表示する。
4. While 検索対象が「ユーザー」または「URL」, the 監査ログビューア shall 選ばれた種類の候補だけを表示する。
5. While 検索対象が「すべて」, the 監査ログビューア shall 種類ごとに表示する候補の件数に上限を設け、一方の種類の候補が多くても、もう一方の種類の候補が表示から押し出されないようにする。
6. When 管理者がユーザーの候補を選ぶ, the 監査ログビューア shall 既存のユーザー名の絞り込みと同じく、一覧をそのユーザーの記録に絞り込む。
7. The 監査ログビューア shall ユーザーの候補に、既存と同じく Active / Inactive の区別を表示する。
8. When ユーザーと URL の両方の値が選ばれている, the 監査ログビューア shall 同じ種類の中ではいずれかに一致し、かつ種類どうしではすべてに一致する記録を一覧に表示する。
9. When 管理者が値を選んでいる状態で「絞り込みを選択」を切り替える, the 監査ログビューア shall 選択済みの値と一覧の絞り込みを保ったまま、以降に表示する候補の種類だけを切り替える。

### Requirement 4: 候補を取得できなかったときの表示

**Objective:** 管理者として、候補の取得要求が失敗したときに、それが「該当なし」ではないと分かるようにしたい。そうすることで、失敗を 0 件と誤解して調査を打ち切らずに済む。

本要件の「候補の取得要求が失敗する」は、候補を取得するリクエスト自体が失敗した場合（通信の失敗、サーバーのエラー応答など）を指す。候補 API が空の候補を返した場合は、理由にかかわらず「該当なし」として扱う（Boundary Context の既知の制約を参照）。入力が 100 文字を超える場合は取得要求そのものを送らないので（1.7）、本要件の対象にならない。

#### Acceptance Criteria

1. If 候補の取得要求が失敗する, the 監査ログビューア shall 検索対象の種類にかかわらず、候補を取得できなかったことが分かる表示を 1 つ出す。
2. If 候補の取得要求が失敗する, the 監査ログビューア shall 選択済みの値と一覧の絞り込みを変えない。

### Requirement 5: 既存の絞り込み操作との整合

**Objective:** 管理者として、新しい検索欄を既存の絞り込みと同じ感覚で使いたい。そうすることで、操作を覚え直さずに済む。

#### Acceptance Criteria

1. When 管理者が検索欄で値を選ぶ、または選択済みの値を外す, the 監査ログビューア shall 一覧の 1 ページ目を表示する。
2. When 管理者が URL と期間・アクションの絞り込みを同時に指定する, the 監査ログビューア shall すべての条件を満たす記録だけを一覧に表示する。
3. When 管理者がリセットを押す, the 監査ログビューア shall 選択済みのユーザーと URL をすべて外し、「絞り込みを選択」を「すべて」に戻す。

### Requirement 6: 多言語対応

**Objective:** 管理者として、普段使っている言語で新しい検索欄を使いたい。

#### Acceptance Criteria

1. The 監査ログビューア shall 本機能で追加する文言（検索欄のプレースホルダ、「絞り込みを選択」とその選択肢、候補の種類ごとの見出し、候補を取得できなかったことの表示）を、en / ja / ko / zh / fr の全ロケールで表示する。
