# Requirements Document

## Introduction

GROWI の Markdown エディタにスラッシュコマンド機能を追加する。ユーザーがエディタのテキスト入力中に `/` を入力するとコマンドメニュー（ポップアップ）が表示され、続けて文字を入力すると候補が絞り込まれ、キーボードまたはクリックで選択すると対応する Markdown 要素（見出し・リスト・コードブロック・テーブル等）が即座に挿入される。これにより、ツールバーのボタンを探す操作なしに、執筆フローを止めず高速に要素を挿入できるようにする。

背景・スコープ・依存関係の詳細は [brief.md](./brief.md) を参照。

## Boundary Context

- **In scope**:
  - エディタのテキスト入力中に `/` でコマンドメニューを表示する
  - 入力文字によるコマンドの絞り込み、キーボード操作（矢印 / Enter / Escape）とクリックによる選択
  - 基本 Markdown 要素の挿入: 見出し（H1–H3）、箇条書きリスト、番号付きリスト、チェックボックス（タスクリスト）、引用、コードブロック、テーブル（プレーンな Markdown テーブルを即挿入）
  - 選択せずにメニューを閉じた場合に入力テキストを保持する誤爆防止挙動
  - コマンドのラベル・説明の多言語表示
  - **対象エディタ**: ページ本文エディタに加え、コメント欄エディタ（`CodeMirrorEditorComment`）も対象に含める。両者は `useDefaultExtensions`（slash + emoji を登録）を共有するため、コメント欄でもスラッシュコマンドが利用できる。コメント欄では別途 `@` メンション補完も併存する（下記 Adjacent expectations）。
- **Out of scope**:
  - GROWI 固有の拡張要素（drawio、math、lsx、テンプレート等）の挿入コマンド（将来拡張）
  - テーブル挿入時の表ビルダー（行列数を指定するモーダル）起動（将来拡張）
  - スラッシュコマンドの並び順・表示内容のユーザーカスタマイズ
  - エディタ外（閲覧モード等）での発火
  - 単語の途中（空白以外の文字の直後）での発火（誤爆防止のため非対応）
  - インライン要素の挿入（将来拡張。MVP のコマンドはすべてブロックレベル要素）
- **Adjacent expectations**:
  - アプリ全体のホットキー `/`（ページ検索）は従来どおり動作する。スラッシュコマンドはエディタのテキスト入力中のみ発火し、グローバル `/` の挙動を変えない。
  - 既存の絵文字オートコンプリート（`:` トリガー）と同時に存在しても互いに干渉しない。
  - コメント欄では `@` メンション補完（dev/8.0.x 由来）とも同時に存在する。slash・emoji・mention はいずれも Markdown language-data の補完ソースとして登録されるため、互いの候補を消さずに共存する（`override` 方式は language-data ソースを置き換えてメンションを壊すため採用しない）。
  - 協調編集（複数ユーザー同時編集）環境でも、挿入が他ユーザーの編集との整合性を壊さない。
  - キーバインド体系（Ctrl+B 等）には影響を与えない。

## Requirements

### Requirement 1: スラッシュコマンドメニューの起動

**Objective:** As an エディタで執筆するユーザー, I want `/` を入力するだけでコマンドメニューを開きたい, so that ツールバーを探さずに要素挿入を開始できる

#### Acceptance Criteria

1. When ユーザーがエディタのテキスト領域で、行頭（先頭の空白文字を除いた行の先頭）または空白文字の直後に `/` を入力する, the スラッシュコマンド機能 shall コマンドメニューをカーソル位置の近傍に表示する
2. If `/` が空白以外の文字の直後（単語の途中、例: `foo/`）に入力される, then the スラッシュコマンド機能 shall コマンドメニューを表示しない
3. The スラッシュコマンド機能 shall メニュー内の各コマンドについて、識別できるラベルを表示する。あわせて、内容を補う短い補助テキスト（Requirement 10 の記法ヒント、または説明文）を持つコマンドについてはそれも表示する
4. While コマンドメニューが表示されている, the スラッシュコマンド機能 shall いずれか1つのコマンドを初期ハイライト状態にする

### Requirement 2: コマンドの絞り込み

**Objective:** As an ユーザー, I want 入力した文字でコマンドを絞り込みたい, so that 目的のコマンドへ素早く到達できる

#### Acceptance Criteria

1. When ユーザーがメニュー表示中に `/` に続けて文字を入力する, the スラッシュコマンド機能 shall 入力文字列に一致するコマンドのみを候補として表示する
2. The スラッシュコマンド機能 shall コマンドの一致判定を大文字・小文字を区別せずに行う
3. When ユーザーが文字を削除して入力文字列が変化する, the スラッシュコマンド機能 shall 候補一覧を最新の入力に合わせて更新する
4. If 入力文字列に一致するコマンドが存在しない, then the スラッシュコマンド機能 shall メニューを閉じ、入力済みのテキストをそのまま残す
5. When 複数のコマンドが一致する, the スラッシュコマンド機能 shall **コマンド名（id）に一致したもの**を、**キーワード（別名）だけに一致したもの**より先に表示する。同順位のコマンド同士は宣言順を保つ（例: `/c` は「コードブロック」を、`checkbox` を別名に持つ「タスクリスト」より先に出す）
6. The スラッシュコマンド機能 shall 照合対象を英語の id とキーワードのみとし、**表示ラベル（ローカライズ済み）は照合しない**。コマンドに到達するための入力が表示言語によって変わらないようにするため（例: 日本語表示でも `/table` で到達し、`/テ` では一致しない）

### Requirement 3: コマンドの選択と要素の挿入

**Objective:** As an ユーザー, I want 候補を選択して対応する要素を挿入したい, so that 手早く Markdown 要素を書き始められる

#### Acceptance Criteria

1. When ユーザーが上下矢印キーを押す, the スラッシュコマンド機能 shall ハイライトされる候補を移動する
2. When ユーザーが Enter キーで候補を確定する、またはマウスで候補をクリックする, the スラッシュコマンド機能 shall 対応する Markdown 要素を挿入し、入力した `/` とそれに続くクエリ文字列を削除する
3. When ユーザーがテーブルコマンドを選択する, the スラッシュコマンド機能 shall ヘッダ行と区切り行を含む空の Markdown テーブルを挿入する
4. When 要素が挿入される, the スラッシュコマンド機能 shall ユーザーが続けて入力できる位置にカーソルを配置する
5. When 要素が挿入された直後にユーザーが取り消し（undo）操作を行う, the スラッシュコマンド機能 shall 挿入された要素を元の状態に戻す
6. When 要素を挿入する際に `/` が行の途中（同じ行に先行する非空白テキストがある位置）にある, the スラッシュコマンド機能 shall ブロック要素を新しい行に挿入し、先行するテキストを壊さない

### Requirement 4: メニューのキャンセルと誤爆防止

**Objective:** As an ユーザー, I want コマンドを使わないときは通常どおり `/` を入力したい, so that 意図しない要素挿入で執筆が妨げられない

#### Acceptance Criteria

1. When ユーザーが Escape キーを押す, the スラッシュコマンド機能 shall メニューを閉じ、入力した `/` テキストをそのまま残す
2. When ユーザーがメニューの外をクリックする、またはエディタからフォーカスが外れる, the スラッシュコマンド機能 shall メニューを閉じる
3. When ユーザーがコマンドを選択せずに、入力した `/` テキストに続けて空白を入力する, the スラッシュコマンド機能 shall 要素を挿入せず、入力されたテキストを変更しない

### Requirement 5: 提供するコマンドセット（初期リリース）

**Objective:** As an ユーザー, I want よく使う基本要素をスラッシュコマンドから挿入したい, so that 主要な Markdown 要素を素早く入力できる

#### Acceptance Criteria

1. The スラッシュコマンド機能 shall 次の要素を挿入するコマンドを提供する: 見出し H1、見出し H2、見出し H3、箇条書きリスト、番号付きリスト、チェックボックス（タスクリスト）、引用、コードブロック、テーブル
2. When ユーザーが見出し・リスト・引用・チェックボックスのコマンドを選択する, the スラッシュコマンド機能 shall 現在の行に対応する Markdown 記法のプレフィックスを付与する
3. When ユーザーがコードブロックのコマンドを選択する, the スラッシュコマンド機能 shall コードを入力できる空のコードブロックを挿入する
4. Where 拡張要素（drawio、math、lsx、テンプレート等）, the スラッシュコマンド機能 shall 本リリースではコマンドを提供しない

### Requirement 6: 既存のエディタ機能との共存

**Objective:** As an ユーザーおよび運用者, I want 既存のショートカットやエディタ機能が従来どおり動作してほしい, so that スラッシュコマンド追加による回帰が起きない

#### Acceptance Criteria

1. While エディタのテキスト領域にフォーカスがない, when ユーザーが `/` を押す, the アプリケーション shall 従来どおりページ検索を起動し、スラッシュコマンドメニューを表示しない
2. The スラッシュコマンド機能 shall 既存の絵文字オートコンプリート（`:` トリガー）と同時に有効であっても、互いの表示・動作を妨げない
3. While 複数のユーザーが同一ページを協調編集している, when スラッシュコマンドにより要素が挿入される, the スラッシュコマンド機能 shall 他ユーザーの編集内容との整合性を保つ
4. The スラッシュコマンド機能 shall 既存のキーバインド（太字 Ctrl+B 等）の動作を変更しない

### Requirement 7: コマンド表示の多言語対応

**Objective:** As an 異なる表示言語を使うユーザー, I want コマンドのラベルと説明が自分の言語で表示されてほしい, so that 内容を理解してコマンドを選べる

#### Acceptance Criteria

1. The スラッシュコマンド機能 shall コマンドのラベルと説明を、ユーザーの表示言語設定に従って表示する
2. If あるコマンドのラベルまたは説明が現在の表示言語向けに用意されていない, then the スラッシュコマンド機能 shall 既定言語のテキストを表示する
3. The スラッシュコマンド機能 shall GROWI がサポートする全ロケール（`en_US` / `ja_JP` / `fr_FR` / `ko_KR` / `zh_CN`）に対して各コマンドの `slash_command.*` ラベル・説明キーを提供する

### Requirement 8: 構造上の文脈に応じたコマンドの絞り込み（試用フィードバック）

**Objective:** As an リスト項目やテーブルセル内で執筆するユーザー, I want その場に挿入すると記法が壊れるコマンドをメニューから除外してほしい, so that 誤って構造を破壊するコマンドを選ばずに済む

#### Acceptance Criteria

1. When ユーザーがリスト項目（箇条書き・番号付き・タスクリストのいずれか）の行内で `/` を入力する, the スラッシュコマンド機能 shall 見出し（H1–H3）・テーブル・コードブロックのコマンドを候補から除外する（いずれもリスト項目内に収まらず、リストを抜けて空の項目を残すため）
2. When ユーザーがテーブルセル内で `/` を入力する, the スラッシュコマンド機能 shall 見出し（H1–H3）・テーブル・コードブロック・引用・箇条書き/番号付き/タスクリストのコマンドを候補から除外する（テーブルセルは改行・ブロック要素を一切含められないため、リスト項目より厳しい制約とする）
3. The スラッシュコマンド機能 shall コマンドごとに除外対象の文脈（`list` | `table`）をデータとして宣言し、絞り込みロジックがそのデータを読んで判定する（文脈ごとにコマンドを個別分岐しない）
4. While リスト項目・テーブルセルのいずれでもない通常の文脈, the スラッシュコマンド機能 shall 全コマンドを絞り込み対象として扱う（本要件による追加の除外を行わない）

> **Out of scope（本要件では対応しない、フィードバック起点の別要望）**:
> - 太字・リンク挿入などの**新規コマンド追加**（選択範囲なしでの空マーカー挿入を想定。`editor-slash-command` は9コマンドの契約を持つため、新規コマンドは別ストーリーで扱う）。方針は確定済み（`tasks.md` の Implementation Notes 参照）だが、9コマンド契約を壊すため本スペックでは実装しない。
> - リスト種別の変換自体は **Requirement 9 で対応済み**（新規「[convert]」コマンドを足すのではなく、既存のリスト系コマンドがリスト文脈で変換として振る舞う形にしたため、9コマンド契約を壊さない）。

### Requirement 9: リスト項目内でのコマンドの振る舞い（試用フィードバック）

**Objective:** As an リスト項目内で執筆するユーザー, I want コマンドがリストの外に飛び出さず、その項目の中で働いてほしい, so that リスト構造を壊さずに種別変換や引用の挿入ができる

前提: 本要件はリスト項目内での `/` 入力を対象とし、位置で2つに分かれる。**内容がリストマーカーのみ**の行（例 `- /`、`  1. /`、`- [ ] /`）は AC 1–2 が同一行を書き換える。それ以外の位置（本文のあるマーカー行、およびその項目の継続行）は AC 5 が新しい行を作りつつ、その項目のプレフィックスを引き継ぐ。いずれの場合もリストの外（列0）には出さない。

対象は Requirement 8.1 でリスト文脈に残るコマンド、すなわち**リスト系（箇条書き・番号付き・タスクリスト）と引用**のみ。リスト項目内に収まらないコマンド（見出し・テーブル・コードブロック）は Requirement 8.1 で候補から除外されるため、本要件の対象外。

#### Acceptance Criteria

1. When ユーザーがリストマーカーのみの行でリスト系コマンド（箇条書き・番号付き・タスクリスト）を選択する, the スラッシュコマンド機能 shall その行の既存マーカーを選択した種別のマーカーへ置換し、インデント（ネスト階層）を維持する（例: `  - /` で番号付きリストを選ぶと `  1. ` になる）
2. When ユーザーがリストマーカーのみの行で引用コマンドを選択する, the スラッシュコマンド機能 shall 改行を挿入せず、その行のリストマーカーを残したまま同一行に引用マーカーを付加する（例: `- /` → `- > `）
3. The スラッシュコマンド機能 shall 各コマンドがリスト文脈でどう振る舞うか（マーカーを置換する / 同一行に付加する）をデータとして宣言し、ビルダーがそれを読んで分岐する（コマンドごとの個別分岐をロジック側に持たない）
4. When 上記いずれかの振る舞いが適用される, the スラッシュコマンド機能 shall 置換を単一トランザクションで行い、undo 1 回で元の状態（`/query` 入力前）に戻す
5. When ユーザーがリスト項目内のそれ以外の位置（本文のあるマーカー行 `- foo /`、またはその項目の継続行 `  bar /`）でコマンドを選択する, the スラッシュコマンド機能 shall 新しい行に**その項目自身の**行頭プレフィックス（インデントおよび引用マーカー）を引き継ぎ、リストの外（列0）に出さない。リスト系コマンドはプレフィックスをそのまま再現して**同じ階層の兄弟項目**にし、引用はプレフィックスを内容カラムまで詰めて**その項目の内側**に置く。プレフィックスはカーソル行ではなく項目のマーカー行から求める（継続行はマーカーを持たないため）
6. While リストのいずれの行でもない位置（通常の文章中・行頭）, the スラッシュコマンド機能 shall Requirement 3.6 の既存の挿入挙動を維持する

> **AC 5 の背景**: 当初は本文のある行を Req 3.6 の既存挙動（列0へ改行挿入）に委ねていたが、それだと引用がリストを抜けてしまい、Requirement 8.1 でコードブロックを除外した根拠（「項目の内側で働くコマンドだけ残す」）と矛盾するとコードレビューで指摘された。調査したところ、**ネストしたリストではリスト系コマンドも階層を失う**（`  - foo /` ＋箇条書きが列0の項目になる）という同じ原因の不具合があり、両方まとめて修正した。プレフィックスは行テキストから導出できるため構文木を参照しない。

### Requirement 10: コマンドの記法ヒント表示（試用フィードバック）

**Objective:** As an ユーザー, I want 単純なコマンドについては冗長な説明文ではなく実際の Markdown 記法を見たい, so that 何が挿入されるか一目で分かり、記法自体も覚えられる

#### Acceptance Criteria

1. Where コマンドの挿入結果が単一行のマーカーで表現できる（見出し H1–H3・箇条書き・番号付き・タスクリスト・引用）, the スラッシュコマンド機能 shall 説明文の代わりにその Markdown マーカー（`#`、`##`、`###`、`-`、`1.`、`- [ ]`、`>`）を補助テキストとして表示する
2. The スラッシュコマンド機能 shall 記法ヒントを翻訳対象に含めない（Markdown 記法は表示言語によらず同一のため、ロケールファイルに置かない）
3. Where コマンドの挿入結果が単一行のマーカーで表現できない（コードブロック・テーブル）, the スラッシュコマンド機能 shall 記法ヒントを持たず、ラベルのみを表示する
4. The スラッシュコマンド機能 shall 記法ヒントと説明文の両方が存在する場合は記法ヒントを優先し、どちらも存在しない場合は補助テキストの領域自体を表示しない（空文字による余白を残さない）

> **AC 3 の判断根拠**: コードブロック・テーブルには説明文を書かない。ラベル（「コードブロック」「テーブル」）だけで内容が自明であり、「説明欄が説明しすぎ」という試用フィードバックの主旨からも、この2つにだけ説明文を残すとかえって不揃いに見えるため。`descriptionKey` と解決経路は温存してあるので、必要になればロケールファイルに文面を書くだけで表示できる（コード変更は不要）。
