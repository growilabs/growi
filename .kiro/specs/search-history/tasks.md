# Implementation Plan

> 方針: タスクはチケットごとに 3 つのグループ（保存 #191670 → 再検索 #191671 → 削除 #191672）に分け、各グループを 1 つの実装 PR にする。グループはこの順に依存し、後のグループは前のグループのマージ後に着手する。各グループは単独でマージしても既存の検索モーダルの挙動を壊さない状態で終える（保存の PR の時点では、記録だけが行われ、画面に履歴は出ない）。
>
> 新規のロジックとコンポーネントは TDD（テスト先行・red → green）で進める。テストは essential-test-design（観察可能な契約を確かめる）と essential-test-patterns（Vitest・RTL・`mock<T>()`）に従う。ファイルの配置・関数の契約は design.md の File Structure Plan と Components and Interfaces に従う。
