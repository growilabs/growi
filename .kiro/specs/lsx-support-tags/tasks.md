# Implementation Plan

- [x] 1. LsxApiOptions にタグオプションの型を追加する
  - `LsxApiOptions` に `tag?: string` を追加し、既存のオプションと同様にオプショナルな文字列として扱えるようにする
  - 観測可能な完了状態: `tag` オプションを渡すコードが型エラーなくコンパイルできる
  - _Requirements: 1.1, 1.2_

- [x] 2. サーバー側でのタグ絞り込みロジックの実装
- [x] 2.1 (P) タグオプション文字列の解析処理を実装する
  - カンマ区切りのタグ名文字列を配列に分解し、各要素の前後の空白を除去し、重複を除去する
  - 値が指定されていない場合（空文字列・値なし指定）にエラーを投げることを確認する単体テストを書く
  - 観測可能な完了状態: 複数タグ・空値・空白入りタグ名を入力した単体テストがすべて成功する
  - _Requirements: 1.1, 1.2, 1.6_
  - _Boundary: parseTagNames_

- [x] 2.2 (P) 解決済みページID一覧をクエリ条件に変換する処理を実装する
  - ページIDの配列を受け取り、既存のクエリに `_id` による絞り込み条件を追加する
  - 空配列を渡された場合でも例外を投げず、0件に絞り込む条件を返すことを確認する単体テストを書く
  - 観測可能な完了状態: 非空配列・空配列それぞれのテストケースが期待した絞り込み条件を返す
  - _Requirements: 1.1, 1.2, 1.4, 1.5_
  - _Boundary: addTagCondition_

- [x] 3. (P) タグ名の集合から、それら全てを持つページのIDを求める処理を実装する
  - 既存の `PageTagRelation` の実装（Prisma拡張）に、タグ名配列を受け取り該当ページID配列を返す処理を追加する
  - 単一タグ指定で一致するページのみが返ることを確認する統合テストを書く
  - 複数タグ指定時にAND（指定した全てのタグを持つページのみ）で絞り込まれることを確認する統合テストを書く
  - 指定したタグ名の一部がタグとして存在しない場合に空配列が返ることを確認する統合テストを書く
  - 観測可能な完了状態: 単一タグ・複数タグ(AND)・存在しないタグ名を含む場合の3パターンの統合テストがすべて期待通りの結果を返す
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5_
  - _Boundary: PageTagRelation拡張_

- [x] 4. (P) $lsx 記法・コンポーネントにタグ属性を追加する
  - 記法解析の許可属性一覧に `tag` を追加し、サニタイズ処理でも保持されるようにする
  - Reactコンポーネントの props とオプションオブジェクトに `tag` を追加する
  - 観測可能な完了状態: `$lsx(/path, tag=...)` の記法から、`tag` 属性が既存のストア層（API呼び出しのオプション組み立て）まで欠落せずに渡ることを確認する既存テストが、`tag` 属性を含めても成功する
  - _Requirements: 1.1, 1.2, 2.1, 2.2_
  - _Boundary: lsx directive parser, Lsx component_

- [x] 5. 一覧取得ルートへのタグ条件統合と依存注入の配線
- [x] 5.1 一覧取得ルートにタグ条件の適用を統合する
  - `tag` オプションが指定された場合に、解析・解決・クエリ条件追加を、既存の `depth`/`filter`/`except` と同じ処理段（件数取得より前）に組み込む
  - `tag` オプションが指定されない場合は既存の処理経路を変更しないことを確認する
  - 観測可能な完了状態: タグ指定あり／なしの両方のリクエストに対する統合テストが、既存オプションとタグ条件がすべてANDで反映された結果を返す
  - _Depends: 2.1, 2.2_
  - _Requirements: 2.1, 2.2, 2.3_

- [x] 5.2 タグ解決処理を注入できるようにルート初期化処理を拡張する
  - `packages/remark-lsx` のルート初期化処理（`middleware(crowi, app)`）が、タグ名からページIDを求める処理を第三引数として外部から受け取れるようにする
  - 受け取った処理を、一覧取得ルートのファクトリへそのまま渡す
  - 観測可能な完了状態: タグ解決処理を渡すテストダブルを使った呼び出しで、初期化処理がエラーなく完了する
  - _Depends: 5.1_
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5_

- [x] 5.3 apps/app 側でタグ解決処理を配線する
  - `apps/app` のルート初期化箇所（`crowi/index.ts`）で、タグ名からページIDを求める実装（タスク3）を注入する
  - 観測可能な完了状態: `$lsx` のルートが実際にタグ条件付きのリクエストを処理し、権限フィルターを適用した上でページ一覧を返す
  - _Depends: 3, 5.2_
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5_

- [x] 6. 結合・回帰確認
- [x] 6.1 (P) 閲覧権限フィルターとの組み合わせを確認する統合テストを追加する
  - 閲覧権限のないページを含むテストデータに対して、タグ指定時の一覧・件数の両方からそのページが除外されることを確認する
  - 観測可能な完了状態: 権限のないページを含む統合テストが、一覧・件数の両方からそのページが除外された結果を返す
  - _Depends: 5.3_
  - _Requirements: 3.1, 3.2_

- [x] 6.2 (P) タグ指定時の表示・追加読み込みのE2E確認を行う
  - `$lsx(/path, tag=...)` を含むページを表示し、対象タグを持つ配下ページのみが階層表示され、合計件数と「もっと見る」が既存と同様に動作することを確認する
  - 観測可能な完了状態: E2Eテストが、タグ絞り込み結果の階層表示・件数・追加読み込みについて期待通りの結果を返す
  - _Depends: 5.3, 4_
  - _Requirements: 4.1, 4.2_

- [x] 6.3 (P) 共有リンクページでの無効化がタグ指定時も維持されることを回帰確認する
  - `tag` 属性を指定した `$lsx` を含む共有リンクページで、既存の無効化表示が変わらないことを確認する
  - 観測可能な完了状態: 共有リンクページの表示テストが、`tag` 属性の有無にかかわらず同じ無効化表示を返す

  - _Requirements: 3.3_
