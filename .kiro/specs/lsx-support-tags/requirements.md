# Requirements Document

## Project Description (Input)

対象: GROWI で `$lsx()` 記法を使ってページ一覧をページ本文に埋め込んでいるユーザー。

現状: `$lsx(/path, ...)` はパス指定の配下（子孫ページ）しか一覧できない。ページをタグでグルーピングして管理している場合でも、パスの階層だけでは一覧を作れない。（元要望: GitHub Discussion #11865）

変更したいこと: `$lsx` にタグによる絞り込みを追加する。

### 事前調査で決めた前提・スコープ（このセッションの調査結果）

- 実現可能。`packages/remark-lsx` は `apps/app` に直接依存しない作りのため、タグ名からページID一覧を求める処理は `apps/app` 側に置き、既存の `listPages({ getExcludedPaths })` と同様に、呼び出し側から関数を渡す形にする。
- タグは単独指定ではなく、既存の `prefix`（パス）指定と組み合わせるオプションとして追加する（例: `$lsx(/path, tag=議事録)`）。パスなし・タグのみの指定は今回のスコープ外。
- 認可（閲覧権限フィルター）は既存の `addConditionToFilteringByViewerForList` をそのまま使い、タグから求めたページIDの一覧（`$in` 条件）と組み合わせる。新規の権限チェックを作らない。
- `depth`・`filter`・`except` は `prefix` を起点とする意味を持つオプションであり、`tag` と同時指定した場合の扱いを要件・設計で明確にする。`num`・`sort`・`reverse` はそのまま使える想定。
- 表示側（`generatePageNodeTree` / `LsxListView`）は変更不要。タグ絞り込み結果は常に `prefix` 配下に限定されるため、既存のツリー構築ロジック（祖先パスを遡って木を組み立てる作り）がそのまま使える。
- 検索機能の `tag:` キーワード（Elasticsearch 依存）は代替にならない。`$lsx` は Elasticsearch 非依存の基本機能のため、別に実装する。
- タグ名からページID一覧を求める処理は、既存の `PageTagRelation`（Prisma 移行済み、`apps/app/src/server/models/page-tag-relation.ts`）と `Tag` モデル（`apps/app/src/server/models/tag.ts`）を使って組み立てる。新規モデルの追加は不要。
- 複数タグを同時に指定した場合は AND（指定した全てのタグを持つページのみ）とする。

## Introduction

`$lsx` は、ページ本文中に書くことで、指定したパスの配下にあるページの一覧を自動的に生成する機能である。現状はパスの階層でしか一覧を絞り込めないため、タグでページを分類しているユーザーが、タグに基づく一覧を作れない。本要件は、`$lsx` にタグによる絞り込みを追加し、パス配下のページ一覧をさらにタグで絞り込めるようにすることを目的とする。

## Boundary Context

- **In scope**: `$lsx` の既存のパス指定（`prefix`）に、タグによる絞り込みを追加すること。ルートパス（`/`）を指定すれば、ウィキ全体を対象にタグで絞り込むことも可能になる。既存のオプション（`depth`・`filter`・`except`・`num`・`sort`・`reverse`）とタグ指定を併用したときの挙動を明確にすること。
- **Out of scope**: パスを一切指定しない「タグのみ」の一覧専用の呼び出し方や、専用のタグ一覧ページの新設。既存の検索機能（`tag:` キーワードによる全文検索）自体の変更。
- **Adjacent expectations**: 閲覧権限による絞り込みは、既存の `$lsx`（パス指定のみ）が提供している挙動と同一のものが、タグ絞り込み時にも適用される。共有リンクページで `$lsx` 自体が無効化される既存の挙動も変更しない。

## Requirements

### Requirement 1: タグによるページの絞り込み

**Objective:** As a ページ編集者, I want `$lsx` の一覧にタグによる絞り込みを指定したい, so that パスの階層に関わらず、タグでグルーピングしたページの一覧を作れる

#### Acceptance Criteria

1. When 編集者が `$lsx` にタグを1つ指定する, the Lsx機能 shall 指定したタグが付いているページのみを一覧に含める
2. When 編集者が `$lsx` に複数のタグを指定する, the Lsx機能 shall 指定した全てのタグが付いているページのみを一覧に含める
3. The Lsx機能 shall タグ名の完全一致によってページを絞り込む
4. If 指定したタグが付いているページが存在しない, then the Lsx機能 shall エラーを表示せず、空の一覧を表示する
5. If 指定したタグ名がウィキ内に存在しない, then the Lsx機能 shall エラーを表示せず、空の一覧を表示する
6. If タグを指定するオプションに値が指定されていない（空である）, then the Lsx機能 shall 他の値必須オプション（`filter` 等）と同様にエラーを表示する

### Requirement 2: パス指定・既存オプションとの組み合わせ

**Objective:** As a ページ編集者, I want タグ指定を既存のパス指定や他のオプションと組み合わせたい, so that 特定のページツリー配下や条件を絞った上で、タグによる絞り込みをさらにかけられる

#### Acceptance Criteria

1. When 編集者がパス指定とタグ指定を同時に行う, the Lsx機能 shall 指定したパスの配下にあり、かつ指定したタグを持つページのみを一覧に含める
2. Where タグの指定が行われていない, the Lsx機能 shall 従来通りパス指定のみによる一覧の挙動を提供する
3. When 編集者がタグ指定と `depth`・`filter`・`except`・`num`・`sort`・`reverse` のいずれかを同時に指定する, the Lsx機能 shall タグによる条件と、それぞれの既存オプションによる条件の両方を満たすページのみを一覧に含める

### Requirement 3: 閲覧権限との整合性

**Objective:** As a ウィキの利用者, I want タグで絞り込んだ一覧にも通常の閲覧権限が適用されてほしい, so that 自分に閲覧権限のないページの存在がタグ絞り込みの一覧から漏れて分かってしまうことがない

#### Acceptance Criteria

1. The Lsx機能 shall タグによる絞り込み結果に対して、パス指定のみの一覧と同一の閲覧権限フィルターを適用する
2. If 閲覧者が、タグの条件に合致するページを閲覧する権限を持たない, then the Lsx機能 shall そのページを一覧および件数に含めない
3. The Lsx機能 shall 共有リンクページにおいて `$lsx` が無効化される既存の挙動を、タグ指定の有無に関わらず維持する

### Requirement 4: 一覧表示・追加読み込みの継続性

**Objective:** As a ページ編集者, I want タグで絞り込んだ場合でも通常の一覧と同じ見た目・操作性を得たい, so that タグ指定によって一覧の使い勝手が変わらない

#### Acceptance Criteria

1. The Lsx機能 shall タグによる絞り込み結果を、パス指定のみの一覧と同じ階層表示の形式で表示する
2. The Lsx機能 shall タグによる絞り込み結果に対しても、合計件数の表示および「もっと見る」による追加読み込みを提供する
