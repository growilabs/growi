# Implementation Plan

> **依存**: 本スペックは基盤 `editor-slash-command` に依存しない（独立実装可）。基底ユーティリティ `toggleMarkdownSymbol`・CodeMirror `showTooltip`・既存 `toolbar.*` i18n キーとツールバーのアイコンを再利用し、見た目は閲覧ページの「Comment」バブルと core-styles の mixin で共有する（design.md 参照）。新規依存ライブラリなし。

- [ ] 1. 基盤: 選択バブルの共通配色を core-styles に切り出し、「Comment」バブルを参照側へ移す
  - mixin と利用側を同時に変更する明示的な統合タスクとする（core-styles と apps/app の 2 パッケージにまたがる）
  - 「Comment」バブルのボタン配色上書き（背景・文字・枠線・ホバー・押下の 9 宣言）を core-styles の共有 mixin として新設する
  - 閲覧ページの「Comment」バブルのスタイルを、同 mixin の参照に置き換える（全テーマで必ず出力される変数だけを使う理由のコメントは mixin 側へ移す）
  - 観測: 置き換え前後で「Comment」バブル用にコンパイルされる 9 宣言が同一であることを確認でき、`turbo run lint --filter @growi/core-styles` と `turbo run lint --filter @growi/app` が通る
  - _Requirements: 3.1, 3.2, 3.3, 7.5_
  - _Boundary: selection-bubble mixin, SelectionActionButton.module.scss_

- [ ] 2. コア: 操作データ・配置計算・バブル DOM・表示状態

- [ ] 2.1 (P) バブルメニューの操作集合をデータ宣言する
  - 太字・斜体・取り消し線・インラインコードを、この表示順で、ツールバーと同じアイコン名・同じ `toolbar.*` 操作名キー・書式記号（取り消し線は `~~`）とともに宣言する
  - 観測: 4 操作が表示順どおりに公開され、各々のアイコン名・操作名キー・書式記号がツールバー/ショートカットと一致することを単体テストで確認できる
  - _Requirements: 1.3, 3.4_
  - _Boundary: selection-palette-operations_

- [ ] 2.2 (P) 中央寄せの基準矩形を算出する純粋関数を実装する
  - カーソル位置の座標矩形とバブル幅から、バブルの水平中心がカーソル位置の水平中心に一致するよう左へずらした基準矩形を返す（上下座標は変えない、幅 0 でも有効な矩形を返す）
  - 観測: 任意の座標と幅について中心が一致し上下座標が保たれること、幅 0 の場合の結果を単体テストで確認できる
  - _Requirements: 2.1_
  - _Boundary: selection-palette-anchor_

- [ ] 2.3 (P) バブル用スタイルモジュールを作成する
  - 「Comment」バブルと同じ外形・影のボタングループと、各ボタンへの共有配色 mixin の適用を定義する
  - CodeMirror tooltip 既定の枠線・背景・余白を打ち消す
  - このスタイルモジュールとそのクラスはバブル DOM（2.4）だけが参照し、ファクトリ（3.1）はスタイルに関与しない
  - 観測: エディタパッケージのビルドで、core-styles の mixin を含むスタイルモジュールが解決・コンパイルされる
  - _Requirements: 3.1, 3.2, 3.3_
  - _Boundary: selection-palette-dom（スタイル）_
  - _Depends: 1_

- [ ] 2.4 バブル DOM を構築し書式トグルに結線する
  - 操作集合（引数で受け取る）の各操作を、小サイズボタン + ツールバーと同じアイコン（「Comment」バブルと同じアイコンサイズ）で表示順に並べ、ルートに 2.3 のスタイルクラスを付ける
  - 各ボタンにツールチップと読み上げ名として、表示言語で解決した操作名を設定する
  - ボタン押下（mousedown）の既定動作を抑止して、押下でエディタのフォーカスと選択を失わないようにする
  - クリックで既存の書式トグル関数を呼び、選択範囲を書式記号で囲む/外す（適用後の選択とフォーカスは既存関数に委ねる）
  - 観測: 単体テストで、4 ボタンが表示順・ツールチップ・読み上げ名を持ち、クリックで `**…**` 等に囲まれて変更後全体が選択され、囲まれた選択での再クリックで解除され、1 回の undo で元に戻り、mousedown の既定動作が抑止されることを確認できる
  - _Requirements: 1.3, 3.4, 4.1, 4.2, 4.3, 4.5, 4.6, 6.1, 6.2_
  - _Boundary: selection-palette-dom_
  - _Depends: 2.1, 2.3_

- [ ] 2.5 (P) 選択・dismiss・フォーカスから表示状態を決める StateField を実装する
  - 「非空選択 かつ 未 dismiss かつ フォーカスあり」のときだけ tooltip を供給し、それ以外は非表示にする
  - Escape 用の dismiss 効果とフォーカス変化の効果を定義し、選択範囲が変わったら dismiss を解除する（効果の発行はファクトリ 3.1 が担う）
  - tooltip の DOM は引数で受け取った生成関数で作る（DOM ビルダーを直接参照しない）
  - tooltip はカーソル側の端（選択の head）を基準に上側優先で表示し、選択範囲との間隔を「Comment」バブルと同じ 8px とし、基準座標を中央寄せの純粋関数で算出する（前方向選択は末尾側・後方向選択は先頭側の文字の座標を使う）
  - 観測: 単体テストで、非空選択で表示・空選択で非表示、前方向/後方向選択で基準位置が末尾/先頭になること、間隔が 8px であること、dismiss 後に非表示となり選択変更で再表示されること、フォーカス喪失で非表示・回復で再表示されること、書式適用後も非空選択なら表示が続くことを確認できる
  - _Requirements: 1.1, 1.2, 2.1, 2.2, 2.3, 2.6, 4.4, 5.1, 5.3, 5.4_
  - _Boundary: selection-palette-tooltip_
  - _Depends: 2.2_

- [ ] 3. 統合: 拡張の合成とエディタへの登録

- [ ] 3.1 バブルメニュー拡張のファクトリを実装する
  - 表示状態を CodeMirror の tooltip 機構へ供給し、上下反転・左右のはみ出し回避・スクロール追従は CodeMirror 標準の挙動に任せる
  - バブル DOM の生成関数（翻訳関数と操作集合を束縛したもの）を表示状態へ渡す
  - Escape はバブル表示中のみ dismiss して消費し（選択は維持）、非表示時は既存のエディタ挙動へ通過させる。Escape 以外のキーは追加しない
  - エディタのフォーカス変化を表示状態へ反映する
  - モジュールの公開面（barrel）はファクトリのみとする
  - 観測: 実 EditorView を使う統合テストで、表示中の Escape で閉じて選択が残ること、非表示中の Escape で既存の選択解除が動くこと、フォーカス喪失で閉じること、ボタンで書式を適用した後もバブルが表示され続けること、Ctrl+B 等の既存キーバインドの結果が変わらないことを確認できる
  - _Requirements: 2.4, 2.5, 2.7, 4.4, 5.2, 5.4, 7.2, 7.3_
  - _Boundary: selection-palette factory_
  - _Depends: 2.4, 2.5_

- [ ] 3.2 エディタの既定拡張にバブルメニューを登録する
  - services-internal の barrel からバブルメニューのファクトリを公開する
  - 既定拡張の Compartment 用引数を組み立てる関数が、スラッシュ拡張に加えてバブルメニュー拡張も受け取れるようシグネチャを変更し、既存テストを更新する
  - 既定拡張の登録フックで表示言語の翻訳関数を注入してバブルメニュー拡張を生成し、既存の単一 Compartment にまとめて登録する（言語切替時は既存どおり再登録で反映）
  - 観測: 既定拡張の構成テストで、外側の配列が長さ 1 のまま（Compartment の重複エラーを起こさない）バブルメニューが含まれることを確認でき、絵文字・スラッシュ補完と同時に登録しても補完とバブルが互いを妨げず、`turbo run test --filter @growi/editor` が通る
  - _Requirements: 6.1, 6.3, 7.1_
  - _Boundary: use-default-extensions_

- [ ] 4. 検証

- [ ] 4.1 自動チェックを通す
  - `turbo run lint`・`test`・`build` を `@growi/core-styles`（lint）・`@growi/editor`・`@growi/app` に対して実行する
  - 観測: すべて green
  - _Requirements: 7.1, 7.2, 7.5_

- [ ] 4.2 実アプリでのスモーク
  - 開発サーバーで、前方向/後方向選択時にバブルがカーソル側の端の上・中央に出ること、エディタ上端付近の行で下側に出ること、左右端付近ではみ出さないこと、スクロールで追従することを確認する
  - 閲覧ページの「Comment」バブルと並べ、ライト/ダークと複数テーマで配色・枠・影・ホバー/押下が一致し、「Comment」バブル自体とツールバーの見た目が変わっていないことを確認する
  - 太字を適用→解除→undo、vim キーマップの visual モードでの Escape、協調編集中の適用が他ユーザーに同期されることを確認する
  - 観測: 上記シナリオがすべて再現する（vim の Escape で不整合があれば 3.1 の優先度を調整して再確認する）
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5, 2.7, 3.1, 3.2, 3.3, 4.1, 4.2, 4.5, 7.2, 7.4, 7.5_
