# Implementation Plan

> コミット方針: 大タスク 1〜5 をそれぞれ 1 コミットにする（1 = 移設のみ、2 = 部品の汎用化、3 = サーバー永続化、4 = クライアント state と初期化、5 = ChatSidebar 組み込み）。移設と機能追加を同一コミットにしない（rename 検出を保つため）。

- [x] 1. 左サイドバー用リサイズ部品を共通コンポーネント配下へ移設する（挙動変更なし）
  - 部品一式（本体、フォールバック、Props 型、スタイル、バレル）をディレクトリごと移動する。移動したファイル自体の内容は変更しない
  - 移動前に、移動対象ファイルが旧ディレクトリの兄弟（左サイドバー側のスタイルや変数）を相対参照していないことを確認し、していれば新しい場所から解決できる参照に直す
  - 左サイドバー本体の参照（部品本体、フォールバック、Props 型、遅延読み込みの参照先）を新しい場所へ向ける。編集はこのファイルに限る
  - 旧ディレクトリへの参照がリポジトリ内に残っておらず、型チェックと Biome リントが通り、左サイドバーの遅延読み込み + フォールバック構造はそのまま
  - _Requirements: 6.1, 6.2, 6.3_

- [x] 2. リサイズ部品を左右どちらのアンカーでも使えるよう汎用化する
- [x] 2.1 ポインタ位置から幅を求める純関数と折りたたみ判定を作り、単体テストで契約を固定する
  - 左アンカーはポインタの横位置、右アンカーはビューポート幅からポインタの横位置を引いた値を幅とし、最小・最大に丸める
  - 最大が最小を下回る指定では最小を優先し、戻り値は常に最小以上・NaN なし
  - 折りたたみ判定は丸める前の幅が最小幅の半分未満のときだけ true（ちょうど半分は false）
  - テストを先に書いて失敗を確認してから実装し、純関数の spec が緑になる
  - _Requirements: 1.3, 2.3, 2.4_
  - _Boundary: computeWidthFromPointer_

- [x] 2.2 リサイズ部品にアンカー・最大幅・折りたたみ省略時のクランプを追加し、ドラッグ操作の契約をテストで固定する
  - アンカー未指定時は従来の左アンカーとハンドル位置のまま。右アンカー指定時はハンドルをパネルの左側に置く修飾スタイルを使う（ハンドルは親の positioned 要素基準で配置されるため、親は overflow を隠してはならない）
  - ドラッグ中は純関数の結果を通知してドラッグ中クラスを付ける。終了時は折りたたみコールバックが渡されているときだけ折りたたみ判定を行い、それ以外は最後の移動で計算した幅を確定通知（一度も動かしていなければ通知しない）してクラスを外す
  - ポインタ位置とビューポート幅はビューポート基準で取得する
  - happy-dom 上でハンドルの押下 → document 上の移動・解放を発火し、右アンカーの幅計算、最大幅での丸め、折りたたみ省略時に閉じず確定通知されること、折りたたみ指定時の従来挙動（左サイドバー回帰チェックに相当）、無効時にハンドルが描画されないことを検証する spec を先に書き、失敗確認後に緑にする
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 1.6, 2.3, 2.4, 6.1, 6.2_
  - _Boundary: ResizableArea_

- [x] 3. (P) チャットサイドバー幅をユーザー UI 設定として既存の更新 API で検証・保存できるようにする
  - 共有の UI 設定インターフェースに任意の数値フィールドを追加する。このフィールドは 4.x のクライアント状態と初期化フックが型として参照する成果物になる
  - Mongoose スキーマに同フィールドを追加する（Prisma スキーマは更新しない）
  - 更新 API のバリデータで「1 以上の整数」のみ受理し、ハンドラの保存対象 allow-list と API ドキュメントの request / response に追加する
  - ログインユーザーは document に、ゲストはセッションに保存され、幅を含まない更新要求では保存済みの幅が変わらない
  - 既存のルート spec に「保存対象に到達する」「省略時は保存対象に含まれない」「ゲストはセッションに書かれる」「バリデータが正の整数を受理し、文字列・0・小数を拒否する」を追加し、先に失敗を確認してから緑にする
  - _Requirements: 3.1, 3.6, 3.7, 3.8_
  - _Boundary: user-ui-settings ルート/モデル, IUserUISettings_

- [x] 4. チャットサイドバー幅のクライアント状態と初期化を用意する
- [x] 4.1 幅の定数・上下限計算・クランプ・グローバル状態・保存スケジューリングを 1 モジュールにまとめ、テストする
  - 初期値 500、最小 360、最大 960、ビューポート予約 320 を定数として持つ
  - ビューポート幅から実効最大幅を求める（960 上限、ビューポート − 320、最小を下回る場合は最小）
  - 永続値を初期化用に丸める（非数・未定義は初期値、範囲外は 360〜960 に丸める。ビューポート非依存）
  - 確定幅は整数に丸めてから保存する（API は整数のみ受け付ける）
  - 幅のグローバル状態は「基底 + 書き込み時に既存の UI 設定保存スケジューラを呼ぶ派生」の 2 段構成とし、確定時に幅フィールド付きで保存がスケジュールされる（既存の debounce にまとまる）
  - 上記の純関数と、保存スケジューラをモックした状態で set 時に幅フィールド付きで呼ばれることを検証する spec が緑になる
  - _Requirements: 2.1, 2.2, 2.5, 3.1, 3.2, 3.4, 3.5_
  - _Depends: 3_
  - _Boundary: chat-sidebar-width_

- [x] 4.2 サーバーから渡る UI 設定で幅状態を初期化するフックを作り、基本レイアウトページの初期化点へ組み込む（小さな統合タスク）
  - feature 内のフックが UI 設定の幅を丸めて基底状態へ hydrate する
  - 基本レイアウトの既存 hydrate 合成点から、左サイドバーの hydrate と同列に呼ぶ（汎用 states から feature を import しない）
  - UI 設定あり／なし／範囲外の 3 ケースで基底状態の値を検証する spec が緑になり、基本レイアウトページでフックが呼ばれている
  - _Requirements: 3.3, 3.5_
  - _Depends: 3_
  - _Boundary: useHydrateChatSidebarAtoms, basic-layout-page hydrate_

- [x] 5. チャットサイドバーにリサイズを組み込む
- [x] 5.1 チャットサイドバー用のリサイズコンテナを作り、画面幅判定・ドラッグ中の幅・確定時の状態更新を担わせる（統合タスク: リサイズ部品、幅状態、デバイス判定を接続する）
  - sm 以上では現在幅（ドラッグ中はローカル値、それ以外はグローバル状態）を右アンカーで渡し、sm 未満では無効化する（全幅は CSS のメディアクエリで上書きし、JS の判定に依存させない）
  - 最大幅は描画時にビューポート幅から算出して渡し、折りたたみコールバックは渡さない
  - 内側に高さ 100% と overflow 隠しを持たせ、横スクロールを出さない
  - 画面幅判定をモックし、sm 以上で幅が style に反映されハンドルが存在すること、sm 未満でハンドルが無いこと、判定が未確定（false）の初回描画でも保存幅で描画されること、sm の判定が切り替わる再描画で表示が追従すること、確定通知でグローバル状態が更新されることを検証する spec を先に書き、失敗確認後に緑にする
  - _Requirements: 1.4, 1.7, 2.3, 3.4, 4.1, 4.2, 4.3, 4.4, 5.1, 5.3_
  - _Depends: 2.2, 4.1_
  - _Boundary: ChatSidebarResizableContainer_

- [x] 5.2 チャットサイドバー本体をリサイズコンテナで包み、固定幅スタイルを撤去する
  - 最外の fixed コンテナをリサイズコンテナに移し、overflow 隠しと幅指定を外す（z-index とスクロールバー補正の margin は維持）
  - スタイルの固定幅（sm 以上 500px）を削除し、sm 未満のみ全幅を維持する
  - 既存のチャットサイドバー spec が緑のまま、リサイズコンテナの spec に「最外コンテナに overflow 隠しクラスが無く、ハンドルがその positioned コンテナ配下に描画される」を追加して緑にする
  - ドロップダウン表示中のずれ無し（5.2）は視覚確認のため 6.2 のスモークで確認する
  - _Requirements: 1.1, 1.7, 4.1, 4.3, 5.1, 5.2, 5.3_
  - _Depends: 5.1_
  - _Boundary: ChatSidebar_
