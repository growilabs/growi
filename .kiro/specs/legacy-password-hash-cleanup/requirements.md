# Requirements Document

## Project Description (Input)
管理画面のセキュリティ設定から、scrypt への移行が済んだユーザーに限って、MongoDB の users コレクションに残る旧 SHA-256 パスワードを削除する機能。

- **誰が困っているか**: GROWI.cloud など、サーバーのシェルに入れない環境の GROWI 管理者。
- **現状**: password-hash-upgrade で、旧 SHA-256 ハッシュを削除する cleanup 用 migration スクリプトと、移行状況を確認する status スクリプトを用意した。しかし、どちらもサーバー上で実行する必要があるため、シェルに入れない管理者は旧ハッシュを削除できず、移行がどこまで進んだかも確認できない。
- **どう変えるか**:
  - 管理画面のセキュリティ設定に、パスワード形式ごとのユーザー数（移行状況）を表示する。
  - 同じ画面から、scrypt への移行が済んだユーザーの旧 SHA-256 パスワード（`password` フィールド）を削除できるようにする。
  - 既存の cleanup スクリプトは残し、削除ロジックを共有する。
  - 未移行（旧ハッシュしか持たない）の ACTIVE ユーザーが残っていても処理を中止しない。移行済みのユーザーだけを対象に削除し、未移行のユーザーには手を付けない。この点で、未移行の ACTIVE ユーザーがいると中止する既存スクリプトとは挙動が異なる。

## Introduction
password-hash-upgrade により、ローカル認証のパスワードは旧形式（SHA-256 + PASSWORD_SEED）から新形式（scrypt）へ、ログイン時に移行される。移行は新形式の保存と旧形式の除去を同時に行うため、ログインを済ませたユーザーの旧形式パスワードはその時点で消える。一方、まだログインしていないユーザーの旧形式パスワードは、弱いハッシュのまま残り続ける。

この機能は、サーバーのシェルに入れない管理者でも、管理画面のセキュリティ設定から移行の進み具合を確認し、まだログインしておらず旧形式パスワードが残っているユーザーが誰かを把握できるようにする。

本書で使う用語:
- **旧形式パスワード**: SHA-256 + PASSWORD_SEED で保存されたパスワード
- **新形式パスワード**: scrypt で保存されたパスワード
- **移行済みユーザー**: 新形式パスワードを持つユーザー。移行の時点で旧形式は除去されている
- **未移行ユーザー**: 旧形式パスワードだけを持つユーザー
- **外部アカウント**: LDAP、OAuth、SAML など、外部の認証方式との連携。外部アカウントでログインするユーザーはローカルのパスワードを検証しないので、ログインしても移行しない
- **催促が必要なユーザー**: 未移行ユーザーのうち、外部アカウントと連携していないユーザー。ローカルのパスワードでログインすれば移行するので、管理者がログインを促す意味がある

## Boundary Context
- **In scope**:
  - 管理画面のセキュリティ設定での移行状況（パスワード形式ごとのユーザー数）の表示
  - 移行を催促すべき未移行ユーザーの一覧の表示（管理者が誰に連絡すればよいかを知るため）
  - 旧形式のパスワードが 1 人分も残っていないときのセクションの非表示
- **Out of scope**:
  - 旧形式パスワードを管理画面から削除する操作。残る旧形式パスワードは未移行ユーザーのものだけで、それが唯一の資格情報のため、削除すればそのユーザーはログインできなくなる
  - 未移行ユーザーへの移行の強制や、催促の実行（メールや通知の送信など）。この機能は催促の相手を示すだけで、連絡は管理者が行う
  - パスワードリセットメールの送信
  - PASSWORD_SEED 環境変数の削除・変更、およびその案内
  - 旧バージョンへ戻す際の準備（password-hash-upgrade の Requirement 4 のとおり、アップグレード前の DB バックアップの復元で行う）
- **Adjacent expectations**:
  - 新形式パスワードを持つユーザーのログイン検証は、すでに新形式だけで行われている（password-hash-upgrade の Requirement 2）。
  - ログイン時の移行では旧形式パスワードが除去される（password-hash-upgrade の Requirement 2.2）。パスワードの設定・変更・リセットでも同様に除去される（同 Requirement 1.5）。この機能はその挙動に依存するだけで、変更はしない。
  - 同一ユーザーに旧形式と新形式の両方を書くリリースは存在しない。旧バージョンは新形式を保存せず、本バージョンは新形式を保存するとき必ず旧形式を除去する（password-hash-upgrade の Requirement 1.5 / 2.2）。そのため、両形式を同時に持つユーザーは存在しない。
  - 外部認証だけを使うユーザーなど、パスワード未設定のユーザーはこの機能の影響を受けない。

## Requirements

### Requirement 1: 移行状況の表示
**Objective:** As a GROWI 管理者, I want パスワード形式ごとのユーザー数を管理画面で確認したい, so that シェルに入らなくても、移行の進み具合を判断できる

#### Acceptance Criteria
1. When 管理者がセキュリティ設定画面を開いたとき, the GROWI 管理画面 shall 「新形式のみ（移行済み）」「旧形式のみ（未移行）」「パスワード未設定」の 3 区分のユーザー数を表示する。
2. The GROWI 管理画面 shall 「旧形式のみ（未移行）」の件数を、アクティブなユーザーと、アクティブ以外（承認待ち・停止中・削除済み・招待中）のユーザーの内訳に分けて表示する。内訳の名前は、内部の定数名（ACTIVE）ではなく各 UI 言語の言葉で書き、アクティブ以外に含まれるステータスを書き出す。
6. If 件数の取得に失敗したとき, then the GROWI 管理画面 shall エラーメッセージとともに再試行の操作を表示し、画面を再読み込みしなくても件数を取得し直せるようにする。
7. When 管理者が画面内の移動でセキュリティ設定画面を開き直したとき, the GROWI 管理画面 shall 以前に取得した件数をそのまま使わず、件数を取得し直す。

### Requirement 4: 権限と表示してよい情報
**Objective:** As a GROWI 管理者, I want 移行状況と未移行ユーザーの情報を管理者だけが見られるようにしたい, so that ユーザーの情報を権限のない利用者に見せずに済む

#### Acceptance Criteria
1. The GROWI サーバー shall 移行状況の取得と、催促が必要なユーザーの一覧の取得を、管理者権限を持つユーザーだけに許可する。
2. If 管理者権限を持たないユーザーが移行状況の取得または一覧の取得を要求したとき, then the GROWI サーバー shall 要求を拒否し、データを返さない。
4. The GROWI 管理画面 shall パスワードやハッシュの値そのものを表示しない。表示するのは、ユーザー数と、Requirement 7 の一覧の項目（ユーザー名、メールアドレス、最終ログイン日時）だけとする。

### Requirement 6: 表示文言の多言語対応
**Objective:** As a 日本語以外の UI 言語を使う GROWI 管理者, I want この機能の表示を自分の UI 言語で読みたい, so that 移行状況と催促の相手を正しく理解できる

#### Acceptance Criteria
1. The GROWI 管理画面 shall この機能で追加する表示文言（見出し、件数の区分名、一覧の項目名、エラーメッセージ）を、GROWI が提供するすべての UI 言語で表示する。

### Requirement 7: 催促が必要な未移行ユーザーの一覧
**Objective:** As a GROWI 管理者, I want 移行を催促すべきユーザーを一覧で確認したい, so that 誰にログインを促せばよいかがわかる

#### Acceptance Criteria
1. When 管理者がセキュリティ設定画面を開いたとき, the GROWI 管理画面 shall 催促が必要なユーザー（旧形式のみを持ち、外部アカウントと連携していないユーザー）を一覧で表示する。
2. The GROWI 管理画面 shall アカウントのステータスにかかわらず、条件に当てはまるユーザーを一覧に含める。
3. The GROWI 管理画面 shall 外部アカウントと連携している未移行ユーザーを一覧に含めない。
4. The GROWI 管理画面 shall 一覧の各行に、ユーザー名、メールアドレス、最終ログイン日時を表示する。ログインしたことがないユーザーには、その旨を表示する。
5. The GROWI 管理画面 shall 最終ログイン日時の新しい順に一覧を並べ、ログインしたことがないユーザーを最後に置く。
6. If 催促が必要なユーザーが一度に読み込む件数より多いとき, then the GROWI 管理画面 shall 一覧の末尾までスクロールしたときに続きを読み込み、最後のユーザーまで見られるようにする。
7. While 催促が必要なユーザーが 0 人のとき, the GROWI 管理画面 shall 一覧の代わりに、催促が必要なユーザーがいないことを表示する。
8. If 一覧の最初の読み込みに失敗したとき, then the GROWI 管理画面 shall 一覧の代わりにエラーメッセージと再試行の操作を表示する。件数の表示には影響させない。
9. If 続きの読み込みに失敗したとき, then the GROWI 管理画面 shall 読み込み済みの行を残したまま、一覧の末尾にエラーメッセージと再試行の操作を表示する。
10. When 管理者が画面内の移動でセキュリティ設定画面を開き直したとき, the GROWI 管理画面 shall 以前に読み込んだ一覧をそのまま使わず、読み込み済みのページを取得し直す。
11. If 読み込み済みのページの取り直しに失敗したとき, then the GROWI 管理画面 shall 読み込み済みの行を残したままエラーメッセージと再試行の操作を表示し、再試行では読み込み済みのページをすべて取得し直す。

### Requirement 8: 移行完了後のセクションの非表示
**Objective:** As a GROWI 管理者, I want 旧形式のパスワードが残っていなければこのセクションを見なくて済むようにしたい, so that 対応の要らない画面が設定画面に残り続けない

#### Acceptance Criteria
1. While 旧形式のみ（未移行）のユーザーが 0 人のとき, the GROWI 管理画面 shall この機能のセクションを表示しない。
3. While 件数を取得している途中のとき, the GROWI 管理画面 shall セクションを表示しない。
4. If 件数の取得に失敗したとき, then the GROWI 管理画面 shall セクションを隠さずに表示し、エラーメッセージを出す。
