# Requirements Document

## Introduction

ページのコメントを API で読む利用者(GROWI MCP の `getComments`、外部のスクリプト、GROWI 自身の画面)が、通常コメントとインラインコメントを1回の呼び出しで取得できるようにする。

本機能は、通常コメントとインラインコメントを1つの一覧で返す取得 API(`GET /_api/v3/comments`、以下「コメント一覧 API」)と、コメントを1件だけ取得する API(`GET /_api/v3/comments/:id`、以下「コメント単体取得 API」)を提供する。一覧の各コメントと単体取得の応答には、そのコメントの絵文字リアクションが含まれる。旧式の `GET /_api/comments.get`(インラインコメントを返さない)は、非推奨(deprecate)としてそのまま維持する。GROWI 自身の画面はコメント一覧 API から取得し、インラインコメント専用の一覧取得 API は提供しない。ページのコメント件数は、インラインコメントも合算して数える。

本スペックは、コメントの「取得と件数」の契約を持ち続ける永続的なスペックである。範囲は取得と件数に限り、コメントの作成、編集、削除は含めない(今後必要になれば追加する)。`inline-comment` と `share-link-comments` は、取得と件数については本スペックに従う(`brief.md` の「関係するスペック」)。

## Boundary Context

- **In scope**:
  - 通常コメントとインラインコメントを 1 本で返す新しいコメント一覧 API
  - 一覧の各コメントに、そのコメントのリアクションを含めること
  - コメントを 1 件取得するコメント単体取得 API
  - 版(リビジョン)を指定した取得
  - 共有リンク経由(ゲストを含む)での取得
  - 新 API の公開仕様への記述
  - 旧式 `comments.get` の非推奨化(挙動は変えない)
  - GROWI 自身の画面が使う取得の、新 API への切り替え
  - インラインコメント専用の一覧取得 API の廃止
  - ページのコメント件数にインラインコメントを合算すること
- **Out of scope**:
  - コメントの作成、返信、編集、削除、解決の API の変更(通常コメントもインラインコメントも従来どおり)
  - 旧式 `comments.get` の挙動変更(インラインコメントを返さない現状を維持する。リアクションも返さない)
  - リアクションのデータ、キーの形式、集計の規則、追加・解除の API(`comment-reactions` スペックが持つ。本機能は、取得の応答にリアクションを載せることだけを持つ)
  - 共有リンク画面でのインラインコメント UI の表示(従来どおり表示しない。API が返すようになるだけで、画面には出さない)
  - GROWI MCP サーバー本体と SDK(別リポジトリ)を新 API に切り替える作業。切り替えるまでは、MCP の `getComments` はインラインコメントを取得できない
- **Adjacent expectations**:
  - リアクションの各項目(絵文字のキー、人数、利用者)の意味と集計の規則は、`comment-reactions` スペックの定義に従う。
  - 共有リンクの有効性の判定と、共有リンク閲覧者を読み取り専用とする方針は、既存の共有リンクの仕組み(`share-link-comments`)に従う。本機能はそれを変えない。
  - ページの閲覧権限の判定は、既存のページ閲覧権限の仕組みに従う。
  - インラインコメントのデータの形(選択文字列、前後文脈、位置、アンカー起点の版、解決状態)は、`inline-comment` スペックの定義に従う。

## Requirements

### Requirement 1: 通常コメントとインラインコメントの一括取得

**Objective:** As a コメントを API で読む利用者, I want ページの通常コメントとインラインコメントを 1 回の呼び出しで取得したい, so that 取得の経路を使い分けずに、そのページの議論をすべて読める

#### Acceptance Criteria

1. When 閲覧権限のある利用者がページを指定してコメントの一覧を要求した, the コメント一覧 API shall そのページの通常コメントとインラインコメントの両方を返す
2. The コメント一覧 API shall 各コメントについて、通常コメントかインラインコメントかを判別できる情報を返す
3. The コメント一覧 API shall インラインコメントについて、選択文字列、前後の文脈、おおよその位置、アンカー起点の版、解決状態(解決日時と解決した人)を返す
4. The コメント一覧 API shall 返信を含むすべてのコメントを 1 つの平らな一覧として返し、返信には親コメントを示す情報を持たせる
5. The コメント一覧 API shall 解決済みのインラインコメントも一覧に含める
6. The コメント一覧 API shall 一覧を作成日時の新しい順に並べて返す
7. The コメント一覧 API shall 投稿者の情報を、メールアドレスなどの非公開の項目を除いた形で返す
8. If ページの識別子の形式が不正である, then the コメント一覧 API shall 入力が不正であることを示すエラーを返す
9. The コメント一覧 API shall 投稿者の情報として、ユーザーの ID、ユーザー名、表示名、プロフィール画像の URL の4つだけを返す。メールアドレス(本人が公開しているものも含む)、外部サービスのアカウントの ID、最終ログイン日時、管理者かどうか、アカウントの状態などは返さない。共有リンク経由のアクセスにも、同じ規則を適用する
10. The コメント一覧 API shall 各コメントに、そのコメントのリアクションを `reactions` として含める。リアクションは絵文字ごとに1つの項目とし、絵文字、その絵文字でリアクションした人数、リアクションした利用者、要求者自身がその絵文字でリアクションしているかを持つ。リアクションした利用者は、要件 1.9 の4項目だけを返す。利用者の情報が無いときは、利用者の ID を返す。要求者がログインしていない閲覧者(ゲスト、共有リンク経由を含む)のときは、要求者自身がリアクションしているかを常に偽とする
11. The コメント一覧 API shall リアクションが1つも無いコメントには空の配列を、リアクションを取得できなかったコメントには `null` を返し、両者を区別できるようにする。リアクションを取得できなくても、コメントの一覧そのものは返す

### Requirement 2: 版を指定した取得

**Objective:** As a コメントを API で読む利用者, I want 特定の版の時点で存在していたコメントだけを取得したい, so that 過去の版を読んだ時点の議論を再現できる

#### Acceptance Criteria

1. When 利用者が版を指定してコメントの一覧を要求した, the コメント一覧 API shall 指定した版の次の版が作成された日時より前に作成されたコメントだけを返す。通常コメントとインラインコメントのどちらにも、返信にも同じ条件を適用する
2. When 指定した版が、そのページの最新の版である, the コメント一覧 API shall 作成日時による絞り込みをせず、そのページのすべてのコメントを返す
3. The コメント一覧 API shall 「次の版」を、同じページの版のうち、指定した版より後に作成された最も古い版とする
4. If 指定した版が存在しない、または対象のページに属していない, then the コメント一覧 API shall 見つからない旨を返し、他のページの版が存在するかどうかを知らせない
5. While 共有リンク経由でアクセスしている, the コメント一覧 API shall 指定された版を無視して、ページ全体のコメントを返す

### Requirement 3: アクセス制御と共有リンク

**Objective:** As a ページの管理者, I want コメントの取得に、ページの閲覧権限と共有リンクの設定を正しく反映させたい, so that 見せてよい相手にだけコメントが届く

#### Acceptance Criteria

1. When ページの閲覧権限のあるログイン済みの利用者が要求した, the コメント一覧 API shall コメントを返す
2. When ページ閲覧の読み取り権限を持つアクセストークンで要求された, the コメント一覧 API shall ログイン済みの利用者と同じ扱いでコメントを返す
3. When 有効な共有リンクを経由して、そのリンクの対象ページのコメントを要求した, the コメント一覧 API shall ログインしていない閲覧者に対しても、通常コメントとインラインコメントの両方を読み取り専用で返す
4. If 共有リンクを経由して、そのリンクの対象と異なるページのコメントを要求した, then the コメント一覧 API shall その共有リンクを無効として扱い、共有リンクを使わない通常のアクセスと同じ判定をする
5. If ページが存在しない、または閲覧権限がない, then the コメント一覧 API shall どちらの場合も同じ応答を返し、ページが存在するかどうかを知らせない
6. If ログインしておらず、有効な共有リンクも経由しておらず、かつサイトがゲストの閲覧を許可していない, then the コメント一覧 API shall 認証が必要である旨を返す
7. While サイトがゲストの閲覧を許可している, the コメント一覧 API shall ログインしていない閲覧者にも、そのゲストが閲覧できるページのコメントを返す
8. The コメント一覧 API shall 共有リンク経由のアクセスに、コメントの作成、編集、削除、解決の手段を与えない
9. If コメントの取得中に予期しない失敗が起きた, then the コメント一覧 API shall 内部の詳細を含まない一般的なエラーを返す

### Requirement 4: 公開仕様への記述

**Objective:** As a API の利用者, I want 新 API の入力、応答、エラーを公開仕様で確認したい, so that MCP や SDK から呼び出す実装を作れる

#### Acceptance Criteria

1. The コメント一覧 API shall 入力(ページ、版)、応答(通常コメントとインラインコメントの項目)、エラー応答を、公開する API 仕様に記述する
2. The コメント一覧 API shall 公開仕様から生成される SDK で呼び出せる形で記述される
3. The 公開仕様 shall 通常コメントとインラインコメントを区別する項目と、インラインコメント固有の項目の意味を説明する

### Requirement 5: 旧式の取得 API の維持と非推奨化

**Objective:** As a 既存の API 利用者, I want 旧式の `comments.get` が当面そのまま使えてほしい, so that 新 API への移行を自分のペースで進められる

#### Acceptance Criteria

1. The 旧式のコメント取得 API(`comments.get`) shall 入力、応答、認可の挙動を現状から変えない
2. The 旧式のコメント取得 API shall インラインコメントを返さない現状を維持する
3. The 公開仕様 shall 旧式のコメント取得 API を非推奨と明示し、置き換え先として新しいコメント一覧 API を案内する
4. The 旧式のコメント取得 API shall 投稿者の情報を、ユーザーの項目からパスワード、API トークン、非公開のメールアドレスだけを除いた形で返し、要件 1.9 の絞り込みは適用しない

### Requirement 6: 画面の取得の切り替え

**Objective:** As a GROWI の利用者, I want 画面の見え方を変えずに、内部の取得だけが新 API に切り替わってほしい, so that 移行によって表示や操作が変わらない

#### Acceptance Criteria

1. When ページ下部のコメント欄を表示する, the GROWI の画面 shall 新しいコメント一覧 API から取得し、通常コメントとインラインコメントを、従来どおり投稿日時の古い順に並べて表示する
2. The ページ下部のコメント欄 shall 通常コメントの返信とインラインコメントの返信を、それぞれの親コメントの下に従来どおり表示する
3. When ページ本文のインラインコメント(ハイライト、ポップオーバー)を表示する, the GROWI の画面 shall 新しいコメント一覧 API から取得し、起点コメントと返信を親子の関係で従来と同じ表示にする
4. When インラインコメントの作成、返信、編集、削除、解決のいずれかを行った, the GROWI の画面 shall 取得済みの一覧を最新の内容に更新する
5. While 共有リンクの画面や検索結果のプレビューのように、従来インラインコメントを表示しない画面を表示している, the GROWI の画面 shall 引き続きインラインコメントを表示しない
6. The GROWI の画面 shall 旧式のコメント取得 API を使わない

### Requirement 7: ページのコメント件数

**Objective:** As a GROWI の利用者, I want ページのコメント件数にインラインコメントも含まれてほしい, so that 件数が、そのページに付いた議論の量を表す

#### Acceptance Criteria

1. The ページのコメント件数 shall 通常コメントとインラインコメントを合算して数える
2. The ページのコメント件数 shall 返信も 1 件として数える
3. The ページのコメント件数 shall 解決済みのインラインコメントも 1 件として数える
4. When インラインコメントまたはその返信が作成または削除された, the GROWI shall そのページのコメント件数を更新する
5. When 本変更の導入前からインラインコメントのあるページの件数を表示する, the GROWI shall 既存のインラインコメントを含めた件数を表示する
6. The GROWI shall コメント件数を表示するすべての画面(サイドバーの最近の更新、ページの側面の表示)で、同じ値を表示する

### Requirement 8: インラインコメント専用の一覧取得 API の廃止

**Objective:** As a GROWI の開発者, I want コメントの取得経路を新 API の 1 本にまとめたい, so that 同じ目的の取得 API が 2 本ある状態を解消できる

#### Acceptance Criteria

1. The GROWI shall インラインコメント専用の一覧取得 API(`GET /_api/v3/inline-comments`)を提供しない
2. The GROWI shall インラインコメントの作成、返信の作成、編集、削除、解決の各 API を従来どおり提供する
3. When インラインコメント専用の一覧取得の URL(`GET /_api/v3/inline-comments`)が呼ばれた, the GROWI shall 見つからない旨の応答を返す

### Requirement 9: コメントの1件取得

**Objective:** As a コメントを API で読む利用者, I want コメントを1件だけ指定して取得したい, so that 一覧を取得し直さずに、特定のコメントの最新の内容とリアクションを読める

#### Acceptance Criteria

1. When 閲覧権限のある利用者がページとコメントを指定して1件の取得を要求した, the コメント単体取得 API shall そのコメントを、コメント一覧 API の1件と同じ形(要件 1.10 のリアクションを含む)で返す
2. The コメント単体取得 API shall 通常コメントとインラインコメントのどちらも、返信も、1件として返す
3. The コメント単体取得 API shall 取得するコメントがページに属することを確かめるため、ページの識別子を必須の入力とする
4. If 指定したコメントが存在しない、または指定したページに属していない, then the コメント単体取得 API shall 見つからない旨を返し、他のページのコメントが存在するかどうかを知らせない
5. If ページが存在しない、または閲覧権限がない, then the コメント単体取得 API shall コメントが存在しない場合と同じ応答を返し、ページやコメントが存在するかどうかを知らせない
6. The コメント単体取得 API shall ログイン済みの利用者、読み取り権限を持つアクセストークン、有効な共有リンク、ゲストの閲覧を許可したサイトのゲストに対して、要件 3.1、3.2、3.3、3.4、3.6、3.7、3.8 のコメント一覧 API と同じ規則でアクセスを判定する。共有リンク経由のときは、そのリンクの対象ページのコメントだけを返す
7. The コメント単体取得 API shall 版による絞り込みを提供しない。版を指定した取得は、コメント一覧 API だけが持つ
8. The コメント単体取得 API shall 投稿者の情報を要件 1.9 と同じ4項目だけにする
9. If コメントのIDまたはページの識別子の形式が不正である, then the コメント単体取得 API shall 入力が不正であることを示すエラーを返す
10. If コメントの取得中に予期しない失敗が起きた, then the コメント単体取得 API shall 内部の詳細を含まない一般的なエラーを返す
11. The コメント単体取得 API shall 入力(コメント、ページ)、応答、エラー応答を、公開する API 仕様に記述し、公開仕様から生成される SDK で呼び出せる形にする
